## 원본과 같은 적용 방식

원본 포맷 함수 `0EED:1E65`가 문자열의 스타일을 선택하고, 원본 FNT 픽셀 출력기가 색상표를 사용한다. 한글도 이 색상표에 따라 가장자리 클래스를 생성한다. 화면명이나 폰트명으로 테두리 사용 여부를 제한하지 않는다.

| 원본 스타일 | 가장자리 2 | 가장자리 3 | 표시 |
|---|---|---|---|
| 10h | 0 | 0 | 테두리 없음 |
| 20h | 0Ch | 0 | 오른쪽·아래 그림자 |
| 30h | 0Ch | 0Ch | 양쪽 가장자리 테두리 |
| 40h | E8h | 0 | 원본의 별도 색 그림자 |

기준 한글판에서 제거됐던 스타일 20h의 가장자리 2 색을 원본 0Ch로 복원했다. `0EED:1F27..1F63` 스타일 분기와 색 설정 명령은 이제 원본과 바이트 단위로 같다. 영문·숫자·괄호 등의 원본 FNT도 이 설정을 그대로 받는다. 이전 시험판의 스타일 30h를 한쪽 그림자로 바꾸던 수정은 제거했다.

한글 출력기 `3D02:00A5`는 원본 색상표에 표시할 가장자리가 있는지를 판별한다. 비트맵 생성 `026D`·`0294`는 본체, 가장자리 2, 가장자리 3 순으로 우선한다. 가장자리 2는 본체를 오른쪽·아래·오른쪽 아래로 1픽셀 옮긴 영역에서 본체를 제외한 부분이다. 가장자리 3은 나머지 8방향 주변 픽셀이다. 원본 NEW6P의 94개 ASCII 글리프 4,311픽셀과 이 클래스 규칙이 정확히 일치한다.

기준판에서 별도로 스타일 30h로 변경됐던 명예의 전당 다섯 호출(`331B:0D75`, `1276`, `129A`, `12BD`, `13A3`)은 원본의 20h로 복원했다. 다른 화면용 옵션 추가, 대화상자 재작성, 특정 버튼 ID 판별, 계급 복사 좌표 변경은 현재 시험판에 넣지 않는다. 타이틀·게임 중 메뉴·도움말·임무 결과·명예의 전당을 포함한 기존 출력 호출이 공통 원본 스타일을 받는다. 생산 숫자와 서식 처리는 기존 호출 구조를 유지한다.

## 유닛·건물 정보창 줄 간격 +1픽셀

사용자가 제공한 건설 위치 지정 안내(`DUNE.ENG #84`)의 두 행이 붙어 보여 정보창 함수 `0EED:0F1A` 안에서만 세로 간격 `DS:[6CFA]`를 1 증가시켰다. 함수 진입 때 기존 값을 스택에 보관하고 반환 전에 복원한다. 함수의 연속된 0 초기화 22개를 같은 값을 쓰는 짧은 명령으로 정리해 공간을 확보했으며, 코드 크기·MZ 배치·재배치 항목은 바뀌지 않는다. 공통 폰트 높이·다른 화면·첫 줄·버튼 좌표는 변경하지 않는다.

`tools/checks/check_unit_info_spacing.py`에서 기존 간격 -2·0·2 각각의 진입·반환을 제한 x86 실행했다. 초기화한 지역 변수와 플래그가 기준과 같으며, 저장한 세로 간격·DI·SI·BP·SP가 올바르게 복구된다. 실제 번역 PAK의 #84를 원래 문자 루프로 출력했을 때 행 Y가 `84,92 → 84,93`으로 바뀌었다. 기존 폰트 픽셀·숫자 포맷 검사도 통과했다. 실제 게임 화면 재확인은 아직 하지 않았다. 보고서는 `unit-info-spacing-check.json`이다.
