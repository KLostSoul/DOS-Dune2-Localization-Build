# EXE 내장 가문 이름 번역

## 2026-10-25 명예의 전당 표시 연결 추가

명예의 전당의 `Atreides` 잔존은 CSV 누락이 아니라 출력 연결 누락이었다. 행 조합 코드 `331B:131B`는 기록의 `+0Ch` 가문 ID를 읽고, `1322..1330`에서 ID×30을 계산하여 `DS:[37EC+BX]`·`[37EE+BX]`의 원본 영문 FAR 포인터를 문자열 결합 함수에 전달했다. 아래의 “5곳에만 적용, 명예의 전당 제외”는 최초 구현 당시의 한계이며 이번에 해소했다.

새 `HallHouseName` 헬퍼는 기존 표시용 이름 조회 `3D02:03FE`를 그대로 사용한다. 따라서 `import/strings/executable_house_names.csv`의 한글 이름을 에디터에서 바꾸면 명예의 전당에도 같은 이름이 표시된다. 현재 6개 이름은 하코넨·아트레이데스·오르도스·프레멘·사다우카·용병이다. 원본 영문 식별자와 가문 정보표, 리소스 파일 선택은 유지한다.

`331B:1322..1330` 15바이트만 같은 길이의 진입 코드로 바꿨다. 오버레이 실제 CS를 보존하고 DS 기준으로 상주 한글 세그먼트를 계산하므로 새 오버레이 재배치 항목이 필요 없다. 헬퍼가 기존 호출에서 요구하는 FAR 문자열 포인터 두 워드를 같은 순서로 스택에 남긴다. 플레이어 이름 복사, 이름·공백·계급 결합, 화면 출력은 원래 명예의 전당 코드다. 저장 기록에는 가문 ID가 유지되므로 기록 문자열 자체를 덮어쓰지 않는다.

빌더의 `tools/fonts.py`가 헬퍼를 조립하고 `runtime_patches.py`의 명예의 전당 진입 패치를 적용한다. `runtime_patches.verify()`에서 진입·복귀 코드와 기존 이름 조회 대상까지 검사한다. 이번 생성본은 기존 정렬 여유 안에 들어가 직전 동일 CSV 생성본과 상주·스택 배치 크기가 같고, DOS/XMS 할당도 추가하지 않는다.

- 생성본: `build/translation-editor-20261025-175917-141755`
- EXE SHA-256: `18e002fefb14e75b13861aa35b885147d8fd734071c7c674d33e2936445ab1f1`
- 실행: 루트 `run_final_build.bat`
- 구현: `tools/runtime_patches.py`
- 검사: `tools/checks/check_hall_house_names.py`, 생성본의 `hall-house-names-check.json`

6가문×12계급 72경우를 실제 행 조합 코드와 원래 strcpy/strcat, 한글 이름 조회 함수로 제한 실행하여 CSV 이름과 계급이 정확히 연결되는 것을 확인했다. 문자열 리소스 조회만 실제 생성 PAK를 반환하는 제한 스텁을 썼다. 기록 16바이트·SP·BP·SI·DI가 유지됐다. 2바이트 토큰·달무리 영문·유니폰트 XMS·전체 테두리·정보창 간격 검사도 통과했다. 새 게임 화면 실행 확인은 아직 하지 않았다.

REA/Ghidra는 원본 MZ의 초기 적재 영역만 자동으로 분석하므로, FBOV에서 위 원본 32바이트를 추출해 합성 MZ 헤더로 감싼 읽기 전용 분석 표본을 사용했다. REA의 선형 주소 `0x1000E`에서 `FF B7 EE 37`이 영문 이름 세그먼트 포인터를 PUSH하는 명령임을 확인했다. 이는 원본 전체 오버레이 실행의 관측이 아니다. 원본 바이트 출처와 REA 관측은 `build/analysis/hall-house-names/rea-evidence.json`에 보존했다.

## 원본 식별자와 표시 문자열

원본 `3342:37EC + 가문ID×30`은 이름 FAR 포인터를 담는다. 이 포인터의 이름 첫 글자는 REGION·멘타트·시나리오 리소스 이름 구성에도 사용된다. 영문 이름을 그 자리에서 한글 토큰으로 덮어쓰면 식별자가 바뀐다. 특히 Atreides와 Ordos는 한글 토큰이 원본 문자열 슬롯보다 길다.

따라서 원본 가문 정보표·영문 식별 문자열을 보존하고, CSV에서 생성한 별도 한글 표시 이름을 기존 확장 모듈의 빈 공간에 배치했다. 이름 50바이트, 6개 오프셋 표 12바이트, 조회 코드 12바이트다. 폰트에 새 음절을 추가하지 않고 기존 639음절 토큰을 사용한다.

- 이름: `3D02:00B3..00DF`, 마지막 용병 이름은 `3D02:0154..0158`.
- 오프셋 표: `3D02:0148..0153`.
- 조회 함수: `3D02:03FE`, AX 가문ID → AX 세그먼트 / DX 오프셋.
- 빈 영역은 기존 어셈블리의 프로시저 끝과 다음 ORG 사이를 사용한다. 기존 지역 설명 간격 함수 `03E0..03FD`, 폰트 데이터와 치트 배치를 보존한다.

## 적용한 출력 경로

| 실제 논리 주소 | 대상 |
|---|---|
| `077B:1724`, `077B:176A` | 유닛 문맥 메시지의 가문 이름, 언어별 인자 순서 두 분기 |
| `156F:2648`, `156F:2686` | 건물 문맥 메시지의 가문 이름, 언어별 인자 순서 두 분기 |
| `1836:27E6` | 선택한 유닛의 상단 설명에 합치는 가문 이름 |

위 5곳에서 이름 조회만 교체한다. 원래 `%s` 포맷, 이름·유닛 문자열 결합과 메시지 출력 호출은 유지한다. 앞선 분석 출력에 표시된 주소에는 코드 범위의 시작값이 중복 가산된 것이 있어, 패치에는 원본 바이트와 일치하는 실제 세그먼트:오프셋을 사용했다.

명예의 전당 기록 문자열 조합 등 나머지 EXE 이름 참조는 이번 5곳 패치에 포함하지 않는다. 리소스 식별·INI 처리 참조도 변경하지 않는다.
