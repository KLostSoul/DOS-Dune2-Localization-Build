# 원본 메뉴의 문자열·폭·채우기 경계

## 원본 메인 메뉴 구성과 출력 경로

오버레이 코드도 조사했다. 아래 `0x49xxx`, `0x50xxx` 값은 **EXE 파일 오프셋**이다. DOS의 CS:IP가 아니다. 오버레이의 FAR CALL 세그먼트 피연산자는 로더 재배치 전의 세그먼트 표 오프셋이므로 그대로 런타임 세그먼트로 해석하면 안 된다. 예를 들어 `00A0 / 8 = 20`번 표 항목은 원본 세그먼트 `0EED`다.

### 메뉴 항목 표

데이터 `3342:219D`, 파일 `0x3A1BD`에 각 6 WORD, 12바이트짜리 목록 네 개가 있다.

| 목록 번호 | 문자열 번호 목록 |
|---:|---|
| 0 | `27, 28, 29, 0, 0, 0` |
| 1 | `27, 28, 92, 29, 0, 0` |
| 2 | `27, 28, 29, 334, 0, 0` |
| 3 | `27, 28, 92, 29, 334, 0` |

`0x49F02–0x49F31`에서 파일 존재 확인 결과와 다른 조건값으로 목록 번호를 만든다. `0x49F66–0x49FA6`은 `목록번호 × 12 + 항목번호 × 2 + 219D`에서 문자열 번호를 읽고 문자열 조회 함수 `0DD4:005F`에 넘긴다. 반환된 DX:AX를 스택의 FAR 문자열 포인터 배열에 저장한다. `0x49FAB–0x49FBA`는 첫 0 항목으로 메뉴 항목 수를 정한다.

### 폭 계산·메뉴 목록·각 행 출력

1. `0x49FE3–0x4A022`가 각 문자열을 `2326:002F`에 보내 가장 넓은 문자열 폭을 찾는다. 이 값으로 패널 크기와 위치를 계산한다.
2. `0x4A159`가 메뉴 목록 출력 함수를 호출한다. 대상은 세그먼트 표 197번의 오버레이 스텁 `32E9:0025`다. 스텁의 코드 오프셋은 `0108`, 데이터 시작은 파일 `0x50390`이므로 실제 함수는 파일 `0x50498`이다.
3. 파일 `0x504F7–0x50578`이 메뉴 행을 순차적으로 순회한다. Y는 원본 폰트의 높이 `DS:[6CFD]`와 추가 행간을 사용한다. 선택 상태에 따라 색상을 고르고, `0x5056C`에서 각 행의 문자열을 `0EED:1E65`로 보낸다.
4. `0EED:1E65`는 폰트·색상·정렬을 설정하고 문자열을 포맷한다. 중앙/우측 정렬에서도 `2326:002F`로 폭을 다시 계산한다. 마지막 `0EED:1FEF`, 파일 `0x15ABF`에서 `29C7:0004`를 호출한다.
5. `29C7:0004`는 문자 폭 조회 → 경계 확인 → 글리프 콜백 `DS:[66D8]` 호출 → X 이동 → 다음 문자 순서로 처리한다. 원본 콜백은 `20AA:07BD`다.

## 현재 한글 출력과 원본 메뉴의 경계

메뉴 항목 표와 패널 크기 계산은 원래 경로를 사용한다. 현재 한글 출력은 문자열 폭 계산과 문자 순회에서 2바이트 토큰을 판독하고, 원본 글리프 드라이버 `DS:[66D8]`를 호출한다. 콜백 포인터를 전역 한글 렌더러로 교체하지 않는다.

### 폭 계산과 문자열 이동

원본 `2326:002F`는 바이트 수와 문자열 포인터로 순회한다. 한글 토큰은 두 바이트이므로 소비 길이를 폭·정렬 계산과 실제 출력에 동일하게 적용해야 한다. 현재 판독기는 문자·소비 길이를 반환하고, 각 순회 함수가 자기 포인터와 카운터를 갱신한다. 반환 IP로 호출자를 추측하거나 부모 프레임의 문자열 포인터를 바꾸지 않는다. 실제 연결은 [출력 인터페이스](../engine/native_output_rebuild.md#한글-토큰과-원본-인터페이스)를 따른다.

메뉴 표의 인덱스는 `27,28,29,92,334`다. 박스 폭은 이 항목들의 출력 폭으로 계산하므로 번역문 길이가 바뀌면 함께 달라진다. 박스 크기 변화만으로 토큰 폭 계산의 정확성을 검증할 수는 없다. 현재 토큰 범위와 셀 폭은 [폰트 규약](../../FONTS.md)을 따른다.

### 작업 페이지 선택

원본 글리프 렌더러의 파일 `0x25F0B`, `20AA:086B`는 `20AA:0E02`를 호출해 출력 대상 세그먼트를 얻는다. 이 함수는 활성 화면 번호를 읽고 `((화면번호 & 1E) × 2)`로 화면 테이블의 WORD 세그먼트를 선택한다.

현재 출력은 한 슬롯의 작업 FNT를 원본 드라이버에 전달하므로 이 페이지 선택도 원본이 수행한다. ES를 `A000h`로 고정해 그리거나 같은 선택 로직을 별도 픽셀 루프로 대체하지 않는다. 글리프를 그린 뒤에는 원본 드라이버의 FNT 캐시를 복원한다.

### 문자 전진의 소유권

글리프 콜백이 호출자의 저장된 X를 먼저 늘리고 원본 문자 루프가 폭을 다시 더하면 전진 거리가 중복된다. 콜백은 글리프를 그린 뒤 반환하며, 다음 문자 위치는 원본 루프가 폭과 간격으로 계산한다. 문자열 폭 계산·실제 전진·중앙 및 우측 정렬은 같은 폭 규약을 사용해야 한다.

## 16×16 메뉴 박스 내부가 검게 남는 원인 — 픽셀 채우기 경계 검사

검은 내부의 원인은 색상표나 한글 글리프 렌더러가 아니라, 메뉴 박스의 솔리드 채우기 함수에 넘기는 포함형 아래쪽 좌표가 화면 높이를 넘은 것이다. 이 경로는 원본 EXE의 함수와 실제 함수 포인터, 팔레트값까지 정적으로 추적했다.

1. 메뉴 오버레이 파일 `0x4A13C`는 `0EED:057F`를 `(1, 2, 13)`으로 호출한다. 원시 FAR CALL의 세그먼트 피연산자 `00A0h`는 FBOV 선택값이며 실제 모듈은 `0EEDh`다. `0EED:057F`는 박스 레코드 13에서 `DS:[4126..412C]`의 사각형 위치와 크기를 읽는다. 원본 함수의 파일 오프셋은 `0x1404F`다.
2. 이 함수는 같은 모듈의 프레임 헬퍼 `0EED:0008`을 호출한다. 헬퍼의 첫 호출은 채우기 플래그를 켠 뒤, `3342:[66F4]`의 함수 포인터를 통해 `20AA:0D3B`를 호출한다. 포인터는 원본 데이터 세그먼트에서 `20AA:0D3B`로 확인된다.
3. `20AA:0D3B`의 원본 명령은 끝 좌표를 포함형으로 처리한다. Y2가 `200` 이상이면 `cmp dx, 0xC8` / `jge` 경로로 채우기 루프 전에 반환한다. 이 함수는 끝 좌표를 화면 안으로 잘라 주지 않는다. 프레임 헬퍼는 그 뒤에 테두리를 별도 그래픽 호출로 그리므로 채우기만 실패해도 테두리는 남는다.
4. 박스 스타일 3의 색상표는 `DS:[35F8 + 3×8]`이며 첫 값은 `E9`다. `IBM.PAL`의 `E9`는 6비트 RGB `(44, 44, 49)`이고 VGA의 6→8비트 확장 결과 `(178, 178, 199)`가 된다. 옆 테두리에서 쓰는 `E8`은 흰색, `EB`는 `(85, 85, 121)`로, 스크린샷의 회색 내부·흰 테두리·남보라색 그림자 조합과 일치한다. 채우기가 건너뛰면 제목 화면의 검정 바탕이 그대로 보이는 설명도 맞는다.

16×16 셀 네 항목의 박스 높이는 `16×4+11=75`다. 기준점 158이면 위쪽 126, 포함형 아래쪽 200으로 채우기 경계를 넘는다. 기준점 157이면 아래쪽 199, 155이면 197이다. 기준점과 높이를 함께 계산해야 한다.

TITLE 그림은 제목 로고이며 메뉴 상자는 런타임 채우기·테두리 코드로 그린다. 검은 내부는 글꼴 색이나 박스 CG 누락뿐 아니라 채우기 함수의 `y2>=200` 거부로도 생길 수 있다.

## 원본 메뉴의 문자열 경로

`ENGLISH.PAK`의 `DUNE.ENG`에는 340개 문자열 오프셋이 있다. 메뉴 문자열은 다음 인덱스에 있다.

| 인덱스 | 원본 문자열 |
|---:|---|
| 27 | Play a Game |
| 28 | Replay Introduction |
| 92 | Load a game |
| 29 | Exit Game |

문자열 ID는 표시 문구와 입력 등록에서 함께 대조한다. 타이틀 목록의 단축키는 별도 입력 경로를 사용하므로, 글리프 출력 수정만으로 단축키 복원을 보장하지 않는다. 현재 입력 연결은 [번역 단축키](translated_shortcuts.md#타이틀-목록)를 따른다.
