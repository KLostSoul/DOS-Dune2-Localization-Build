# 한글 명령의 단축키 판독과 원본 입력 경로

원본은 영문 표시 문자열의 첫 글자를 단축키로 사용한다. 표시만 한글로 바꾸면 첫 바이트가 한글 토큰이 되어 A·M 같은 영문 키와 일치하지 않는다. 번역문에는 `공격(A)`, `이동(M)`처럼 대문자 접미사를 표시하고 해당 문자를 원래 키 변환기로 전달한다.

## 공통 키 등록

원본 변환기 `27DE:00DA`는 문자 하위 바이트로 `CS:000C` 표를 조회한다. 한글 선행 바이트가 문자열의 첫 바이트와 일치하면 문자열 끝 괄호 안의 문자를 읽어 같은 표를 사용한다. 기존 ASCII·숫자·Esc·고정 키·보조 취소 키와 원래 위젯 저장·명령 실행을 유지한다.

| 원본 경로 | 역할 |
|---|---|
| `08F5:0BD0` 이후 | 생산·건설 문자열 `[9871]`의 키 |
| `08F5:0F52` 이후 | 일반 명령 `[BP-0E]`의 키 |
| `0EED:15C2` 이후 | 대화상자 위젯 +38h의 문자열 |
| `32BB:0FDE` 이후 | 공통 위젯과 취소 보조 키 |
| `3298:16A0` 이후 | 생산 창의 문자열 기반 위젯 키 |

키 표는 대소문자 쌍을 같은 코드로 변환한다. 접미사의 ASCII 바이트는 글리프 선택과 별개이며 달무리 괄호·영문으로 그려도 입력 코드가 달라지지 않는다.

## 타이틀 목록

타이틀은 `32E9:0200`의 별도 목록 선택 함수다. 문자열 첫 바이트와 실제 입력을 각각 `32E9:03C8`, `03DD`에서 변환해 비교한다. 두 호출을 접미사 지원 `27DE:00DA`로 연결한다. FBOV selector `0288h`와 fixup 슬롯 `03CBh`, `03E0h`를 사용한다. 원래 마우스·방향키·Enter 선택은 보존한다.

## 생산 선택 창

`3298:159D` 이후 위젯 생성은 selector `0328h`의 14바이트 레코드 13개를 읽는다. +6 값이 양수이면 문자열 ID, 음수이면 고정 키다. 그림에 보이는 버튼 글자와 내부 키 문자열은 별개다.

| ID | 원문 | 단축키 |
|---:|---|---|
| 188 | Resume Game | R |
| 189 | Upgrade | U |
| 190 | Send Order | S |
| 191 | Build This | B |
| 192 | Invoice | I |

Resume Game 326번과 생산 창의 188번, Build it 41번과 Build This 191번은 서로 다른 항목이다. 같은 뜻의 번역만 비교해서 키를 배정하면 실제 호출 ID를 놓칠 수 있다.

## 검사

번역문 접미사, 공통 위젯·타이틀 목록·생산 창의 서로 다른 등록 경로와 원래 키 변환 표를 함께 검사한다. 키 처리 때문에 별도의 게임 입력 루프를 만들거나 플레이어 명령 버튼을 추가하지 않는다.
