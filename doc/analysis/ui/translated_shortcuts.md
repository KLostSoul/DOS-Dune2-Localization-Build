# Dune II 한글 번역 후 명령 단축키가 동작하지 않는 원인

작성일: 2026-10-21

최신 상태: [현재 빌드·누적 확인 결과](../../STATUS.md). 아래의 각 ‘현재’·‘확인 전’ 문구는 해당 수정 당시의 이력이며 마지막 사용자 확인 항목이 최신 상태다.

## 현상

게임 명령은 영문 명령 이름의 첫 글자를 단축키로 사용한다. 원본에서 `Attack`의 `A`, `Move`의 `M`으로 실행되던 명령이 해당 텍스트를 한글로 바꾼 뒤 작동하지 않는다.

## 확인한 번역 데이터

번역 원본 [`source_strings_complete_ko_draft.csv`](../../../import/strings/source_strings_complete_ko_draft.csv)는 `DUNE.ENG` 문자열표의 다음 항목을 바꾼다.

| DUNE.ENG 인덱스 | 원문 | 번역 |
|---:|---|---|
| 1 | `Attack` | `공격` |
| 2 | `Move` | `이동` |

따라서 화면 문자열에서 각각 영문 첫 글자 `A`, `M`이 제거된다. 한글 조합 토큰은 화면에 글리프를 고르는 데이터이며, 키보드의 `A`·`M` 입력을 나타내지 않는다. 명령 문자열의 첫 글자를 단축키로 쓰는 기존 동작과 한글 문자열을 그대로 대체한 결과가 충돌한다.

## 원인

번역 과정에서 표시 문자열만 바꾸고 원래 명령의 단축키 정보는 별도로 보존하지 않았다. 게임은 원래 영문 이름의 첫 글자를 기준으로 명령을 찾으므로, 한글로 덮어쓴 항목에는 기존 `A`·`M` 연결이 남지 않는다.

번역표 행은 [`DUNE.ENG` 인덱스 1·2](../../../import/strings/source_strings_complete_ko_draft.csv)에서 확인했다. 번역 적용 보고서 [`translation-application-report.json`](../../../build/analysis/cleanup-2026-10-24/evidence/discarded/dalmuri639-wrapfix/korean/translation-application-report.json)은 이 후보가 해당 CSV를 `DUNE.ENG`에 적용했음을 기록한다.

치트 키 후크가 일반 단축키를 삼킨 것으로 보이지 않는다. [`verified-cheat-rebased.asm`](../../../build/analysis/cleanup-2026-10-24/evidence/discarded/dalmuri639-wrapfix/verified-cheat-rebased.asm)의 `ChainOriginal` 경로는 원래 처리기로 상태를 복원해 넘기며, `AfterKeyHook`은 소비 대상으로 표시된 입력만 별도로 처리한다. 이 코드만으로 각 게임 명령의 A/M 연결을 추적한 것은 아니지만, 번역표의 영문 첫 글자가 사라진 사실과 현재 증상에 부합한다.

## 필요한 수정

화면에는 한글 명령을 표시하면서 키 연결은 원본과 같이 유지해야 한다. 즉, 명령 텍스트를 한글로 바꾸더라도 `A`는 `Attack` 동작에, `M`은 `Move` 동작에 계속 연결되어야 한다. 이를 위해 표시 문자열과 단축키/명령 ID를 분리해 보존하거나, 명령 입력 경로에서 원래 단축키를 해당 동작 ID에 직접 연결해야 한다. 화면 문자열 앞에 영문자를 노출하는 방식은 필요하지 않다.

## 상태 및 범위

- 이번 기록은 번역 데이터와 기존 키 후크의 정적 경로를 근거로 한다.
- 게임 데이터나 실행 파일은 이 문서 작성에서 변경하지 않았다.
- 이 문서는 `Attack`과 `Move`에서 확인된 사례를 기록한다. 다른 명령의 단축키도 번역 전후 표를 대조해 별도로 감사해야 한다.

## 2026-10-22 전체 표시 항목의 단축키 복원 수정

사용자가 유닛 명령뿐 아니라 앞서 나열한 메뉴·생산·수리·설정 항목까지 작동하도록 요청했다. 현재 번역 대응 53개 문자열을 `editor/game_shortcuts.csv`에 모으고 기존 번역 CSV에도 `(영문자)` 표기를 반영했다. 같은 영문이 서로 다른 문자열표 인덱스에 있는 경우도 각각 포함했다.

### 실제 키 등록 경로

원본 키 변환 함수 `27DE:00DA`는 인자 문자값의 하위 바이트를 자체 표 `CS:000C`의 인덱스로 사용한다. 문자열 첫 바이트를 읽고 이 함수를 호출하는 경로를 확인했다.

- `08F5:0BD0` 이후: 건설·생산 버튼의 현재 문자열 `[9871]`에서 키를 구성한다. 진행률 표시 상태에서는 문자열 40번 ‘On hold’의 키를 별도로 사용한다.
- `08F5:0F52` 이후: 일반 명령 버튼의 문자열 ID `[BP-0E]`에서 키를 구성한다.
- `0EED:15C2` 이후: 대화상자 위젯의 문자열 ID `+38h`에서 키를 구성한다.
- `32BB:0FDE` 이후: 공통 위젯 생성기가 문자열을 읽어 같은 변환 함수에 전달한다. 취소 버튼의 기존 보조 키도 유지한다.
- `3298:16A0` 이후: 문자열 기반 위젯 키를 변환한다. 음수로 저장된 고정 키는 다른 분기를 사용하므로 수정하지 않는다.
- `32E3`, `3314`, `331B`의 나가기·예/아니요·진행·명예의 전당 버튼에도 같은 문자 변환 호출이 있다.

기존 `27DE:00DA`의 키 표에서 a/A, m/M, r/R, g/G, h/H, s/S, d/D는 각각 동일한 값이다. 새 표시의 소문자를 기존 키 코드로 변환할 수 있다.

### 구현

1. 먼저 생성했던 `dalmuri672-command-shortcuts`는 유닛 버튼 한 곳에만 전용 접미사 판독기를 연결한 단계였다. 이 빌드를 기준으로 원본 공통 변환 함수의 `27DE:00DE` 인자 준비 부분에 후크를 추가했다.
2. 인자가 한글 lead 범위이고, 원본 호출자가 보존한 ES:BX 문자열의 첫 바이트와 일치할 때만 해당 문자열 끝의 `(x)`에서 x를 읽는다.
3. 이후 원본 `CS:000C` 키 변환 표와 위젯 키 저장·명령 실행 경로를 그대로 사용한다. 키를 해석하는 별도 게임 입력 루프를 만들지 않는다.
4. 기존 ASCII 입력, 고정 키, 숫자·Esc 및 별도 보조 키는 원래 처리에 남긴다. 접미사가 없는 문자열은 기존 첫 바이트를 사용한다.
5. 현재 빌드의 한글 문구에 접미사를 추가했다. 원본 메뉴에서 의도적으로 짧게 바꾼 ‘불러오기’ 등의 문구도 유지한다.

코드 배치는 기존 빈 확장 공간 `3D02:00EB..00FE`, `3D02:1F81..1F99`를 사용한다. 기존 접미사 판독기는 `3D02:040A`이다. 호출자는 원본의 BX 보존 스택 프레임을 사용하며 추가 SI/DX 보존을 마친 뒤 복귀한다. MZ 재배치 항목 하나를 추가했으며 EXE 길이·상주 이미지·XMS 할당은 증가하지 않는다.

## 2026-10-22 타이틀 메뉴 P/R/L/E/H 미동작 원인과 수정

사용자가 타이틀 메뉴의 P·R·L·E·H가 동작하지 않는다고 확인했다. 앞선 ‘전체 항목 연결’ 설명은 타이틀 목록 전용 입력 경로를 누락한 것이었다.

타이틀 목록은 공통 위젯 키 등록 함수가 아니라 `32E9:0200`(원본 파일 `50590h`)의 목록 선택 입력 함수를 사용한다. 이 함수의 원본 파일 `50753h`는 항목 문자열의 첫 바이트를 직접 읽는다. `32E9:03C8`에서 그 문자를 C 라이브러리 대문자 변환기 `0000:10C3`에 전달하고, `32E9:03DD`에서 실제 키 입력도 같은 변환기에 전달한 뒤 비교한다. 한글 lead와 ASCII P/R/L/E/H는 이 경로에서 일치하지 않는다. 기존에 수정한 `27DE:00DA`는 호출하지 않았으므로 접미사 표기를 추가해도 타이틀 메뉴 키는 복구되지 않았다.

`build/dalmuri672-title-shortcuts`에서 위 두 FAR CALL을 기존 접미사 판독이 연결된 키 변환기 `27DE:00DA`로 바꿨다. Borland 세그먼트 피연산자는 selector `0288h`를 사용하며, 원본 세그먼트 표 81번이 `27DE`임을 대조했다. 원래 오버레이 fixup 표의 `03CBh`, `03E0h` 슬롯을 그대로 사용한다. 항목 쪽은 괄호 안의 영문자를, 입력 쪽은 키 입력 문자를 동일한 원본 키 코드로 변환한 후 기존 비교·선택 처리를 수행한다.

이 수정은 목록 입력 함수의 문자 비교 두 곳에만 적용된다. 마우스·방향키·Enter 선택과 메뉴 항목 수, 배치 및 실행 분기는 유지한다. 기존 메뉴 테두리 제거·원본 괄호·대문자 표시와 다른 화면 수정도 유지한다. 파일 길이·상주 이미지·추가 할당은 늘지 않는다.

실행: 루트 `듄2_한글테스트.bat`.

## 2026-10-22 생산 선택 화면의 Build This / Resume Game 누락 수정

사용자가 생산 선택 화면의 BUILD THIS와 RESUME GAME 단축키가 동작하지 않음을 보고했다. 해당 버튼의 표시 글자는 언어별 SHP 그림이며, 키 등록 문자열은 별도 DUNE.ENG 항목에서 읽는다.

원본 생산 위젯 생성 `3298:159D` 이후는 selector `0328h`(세그먼트 표 101번)의 14바이트 레코드 13개를 읽는다. 레코드 +6의 키 값은 `-2,-3,-4,-5,-1120,-1122,188,189,-13,-12,192,191,190`이다. 양수 다섯 개는 `3298:16A0`의 문자열 조회와 기존 키 변환 함수로 전달된다. 음수 값은 고정 키의 별도 처리이며 변경하지 않는다.

앞선 53개 목록은 같은 뜻/비슷한 영문의 다른 문자열 ID만 포함하여 이 다섯 개를 누락했다. 예를 들어 Resume Game 326번은 명예의 전당 쪽 항목이며 생산 선택 화면은 188번을 사용한다. Build it 41번과 Build This 191번도 다르다. 그림이 영어로 보이더라도 내부 키 문자열은 이미 한글이므로 접미사가 없는 상태에서는 첫 한글 바이트로 키가 등록됐다.

| 문자열 ID | 원문 | 한글 키 문자열 | 키 |
|---:|---|---|---|
| 188 | Resume Game | 게임 재개(R) | R |
| 189 | Upgrade | 개량(U) | U |
| 190 | Send Order | 주문 전송(S) | S |
| 191 | Build This | 건설(B) | B |
| 192 | Invoice | 내역(I) | I |

현재 PAK의 다섯 문자열에 ASCII 접미사를 추가해 기존 접미사 지원 키 변환기에 연결했다. `game_shortcuts.csv`와 전체 번역 CSV에도 반영했다. 총 문자열 항목은 58개다. 화면 버튼 CG 자체는 변경하지 않았다.
