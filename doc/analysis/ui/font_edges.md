## 적용 조건

글꼴 종류로 테두리 여부를 판별하지 않는다. 원본 문자열 출력 함수 `0EED:1E65`가 각 문자열의 옵션 스타일을 먼저 적용하고, 그 스타일이 그래픽 드라이버의 픽셀 색상 변환표를 설정한다. 원본 픽셀 출력기 `20AA:07BD`는 글리프 픽셀 값 2·3을 `CS:0093`·`CS:0094`의 변환값으로 바꾼다.

2026-10-22 당시 사용자 지시: 메뉴에는 한글 테두리를 추가하지 않는다. 기존 실측 `build/analysis/original-font-engine/runtime-debug/extended/summary.json`에서 게임 메뉴와 저장·불러오기·설정 행은 옵션 `0x22/0x122`, 가문 설명은 `0x32`였다. 타이틀 메뉴 옵션 `0x22`는 원본 FNT 엔진 분석 문서에 별도로 실측되어 있다. 옵션의 스타일 니블 `0x20`은 테두리 색상표 두 값을 `0x0C,0`으로, 설명용 `0x30`은 `0x0C,0x0C`로 설정한다. 2026-10-25 요청으로 타이틀 메뉴에도 기존 `0x30` 스타일 적용 대상을 추가했다.

후크의 조건을 `CS:[0093..0094] == 0x0C0C`일 때만 테두리를 생성하도록 바꿨다. 메뉴 스타일 `0x10/0x20/0x40`은 기존 달무리 본체 8×8과 원래 Y 위치를 사용한다. 설명용 `0x30`에서만 본체 주변에 인덱스 2·3의 테두리를 생성한다. 폰트 종류로 구분하지 않는다.

이전 후보(`839a47b2…4387e66c`)의 '둘 중 하나라도 0이 아니면 테두리' 조건은 메뉴 스타일 `0x20`까지 허용한 오류였다. 해당 후보 폴더를 지우고 정상 기준 INFO 수정판에서 다시 생성했다.

## 첫 시험본에서 메뉴 글자가 사라진 원인

실패한 첫 시험본(`89880c7f220a6a1e90ed13253cd77322740e3889319cd656fd0d31a6941e4077`)은 삭제했다. 테두리 경로에도 `mov di,0449h`를 추가해 다시 정적 빌드했다. 현재 후보의 어셈블리 목록에서 이 명령이 `OutlineRow`보다 앞에 있고, 두 분기 모두 같은 작업 비트맵을 대상으로 하는 것을 확인했다. 수정판은 아직 게임에서 실행하지 않았다.

## 설명문 아래 1픽셀 공백

사용자 캡처에서 멘타트 설명문의 위아래 글자가 붙어 보였다. 원본 `29C7:0004`는 활성 FNT 높이를 함수 지역 변수에 저장하고, CR과 자동 줄바꿈에서 그 높이에 `DS:[6CFA]`를 더해 Y를 이동한다. 8픽셀 폰트의 줄 피치 8은 한글 테두리 높이 10보다 작다.

설명 스타일 `0x30`에서 줄 피치를 최소 11픽셀로 계산하도록 수정했다. 첫 줄 위치는 유지하고, 테두리를 포함한 높이 10 아래에 빈 1픽셀이 남는다. `29C7:0029`의 원본 높이 읽기 6바이트를 명시적인 높이 계산 헬퍼 호출로 교체했으며, 원본의 지역 변수 저장·CR·자동 줄바꿈·문자 순회 코드는 그대로 사용한다. 헬퍼는 AX로 높이만 반환하며 전역 폰트 메트릭이나 호출자의 스택 프레임을 수정하지 않는다.

헬퍼는 확장 모듈의 빈 구간 `0026h`·`0126h`에 들어가 모듈 크기 7,568바이트를 유지한다. FAR 호출용 MZ 재배치 항목 `(29C7:002C)` 하나를 헤더에 추가했다. 상주 이미지 크기 증가는 없다.

원본 렌더러 명령을 사용하는 제한 CPU 검사에서 `NEW6P/NEW8P` 각각 CR과 자동 줄바꿈의 출력 Y 차이 11, 두 줄 사이 전체 320픽셀 행의 공백을 확인했다. 메뉴 스타일의 모든 639개 음절과 한 줄·여러 줄 메뉴 문구는 기준 INFO 수정판과 화면 픽셀 및 렌더러 호출 좌표가 일치했다. 실제 게임 확인은 사용자 확인 전이다.

### 멘타트 그림 내부의 짧은 설명: 누락된 별도 행 경로

위 CR 검사만으로는 사용자가 보여 준 그림 내부 설명의 간격을 확인할 수 없었다. 해당 짧은 설명은 `3208:3D5B`가 `3208:4787` 행 출력 함수를 호출하는 별도 경로다. `4787`은 각 NUL 종료 문자열을 `0EED:1E65`에 따로 전달하고, `47EE`에서 `add si,[bp+0Eh]`로 다음 행 Y를 계산한다. 호출부 `3D41`의 `mov ax,8 / push ax`가 이 간격을 고정 8로 전달하므로 공통 문자 루프의 CR 높이를 바꿔도 이 구간에는 적용되지 않았다.

이번 수정은 해당 호출 인자만 `8 → 11`로 변경했다. 현재 EXE 파일 `0x50E70`의 `B8 08 00`을 `B8 0B 00`으로 교체하며, 행 출력 함수와 첫 줄 좌표는 그대로다. 별도 코드·재배치·메모리 증가는 없다.

검사에 실제 현재 PAK의 `MENTATA.ENG` 10번 건설 야드 설명에서 `*` 이후부터 FF 이전까지 세 줄을 추출했다. 원본 `3208:4787` 명령을 제한 CPU에서 실행하고 포맷 함수 경계의 세 호출을 관측하여, 시작 Y=30에서 `30,41,52`가 전달됨을 확인했다. 기록한 문자열과 좌표를 실제 원본 문자·픽셀 루프에 전달한 결과 두 줄 사이 화면 행 39·50은 전체 320픽셀이 빈 배경이었다. 게임 실행 확인은 하지 않았다.

## 2026-10-22 메뉴 단축키 영문 테두리 제거

사용자가 메뉴 단축키 영문에 테두리가 남아 있음을 지적했다. 앞서 ‘메뉴에 테두리가 없다’고 답한 것은 한글 조합 출력기의 스타일 판별만 확인한 잘못된 설명이다. 한글은 정확한 `0C0Ch` 매핑(스타일 30h)에서만 테두리를 만들지만, 기존 영문 FNT의 가장자리 픽셀은 스타일 20h의 `0Ch,00h` 매핑에서도 한쪽 테두리를 출력한다. 원본 FNT로 되돌린 괄호 역시 이 매핑을 따른다.

현재 `build/dalmuri672-menu-no-outline`에서 공통 포맷 함수 `0EED:1F3D`의 메뉴 스타일 20h 가장자리 색을 `0Ch,00h → 00h,00h`로 바꿨다. 수정은 테두리 색 설정의 즉시값 1바이트다. 메뉴의 영문·숫자·괄호를 포함한 원본 FNT 가장자리가 투명해진다. 글자 본체 색과 좌표·폭·단축키 연결·대문자 표기는 유지한다.

스타일 10h는 원래 가장자리 색이 0이고, 명예의 전당 및 설명에 적용한 스타일 30h의 `0Ch,0Ch`는 바꾸지 않았다. 폰트 자산과 메뉴 박스 테두리도 바꾸지 않았다. 파일 크기·메모리 배치 증가는 없다.
