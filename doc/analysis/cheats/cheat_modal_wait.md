## 기존 문제와 이전 실패 방식

기존 키보드 후크는 키 입력 때만 창을 그렸으므로, 게임 루프의 전장 변경 구역 복사가 진행되면 같은 표시 페이지의 창을 덮었다. 이 경로는 앞선 원본 역분석에서 특정했다.

매 프레임 시작에 창을 지우고 끝에 다시 그린 후보는 사용자 확인에서 깜박였다. 전역 복사 제한과 메뉴 호출 감싸기를 넣은 다음 후보도 실패하여 철회했다. 이번 후보는 전역 화면 복사 함수·메뉴 호출·매 프레임 결과 평가 함수에 새 후크를 넣지 않는다.

## 현재 실행 순서

이미 사용하던 정상 게임 루프 후크 `044B:0309 → module:02A0` 안에서 입력창을 처리한다. 새 원본 패치 지점이나 새 재배치 항목은 없다.

1. 원본 페이지 0 선택의 메모리 쓰기와 AX의 이전 페이지 반환값을 재현한다.
2. 창 열림 요청이 없으면 즉시 원본 루프로 복귀한다.
3. 열림 요청이 있으면 이전 게임 루프의 전장 갱신이 끝난 표시 화면에서 128×32 배경을 기존 4 KiB XMS에 저장한다. 저장 실패면 화면을 그리지 않고 입력 상태를 닫는다.
4. 창을 한 번 그리고, 입력 내용·상태가 바뀐 경우만 다시 그린다.
5. 입력 대기는 `STI; HLT`를 사용한다. 하드웨어 인터럽트를 허용하여 키보드가 계속 동작하지만, 원래 게임 루프의 전장 갱신·복사 호출로는 진행하지 않는다.
6. 빈 Enter·Esc·유효 명령으로 닫히면 배경을 한 번 복원하고 원본 게임 루프를 재개한다.

창이 표시된 동안 전장 작업이 진행되지 않으므로, 이번 방식에서는 저장한 배경이 전장 진행으로 낡지 않는다. 매 프레임 창을 지워 전장을 잠깐 노출하는 처리도 없다. 대기 중 하드웨어 타이머와 게임이 인터럽트에서 갱신하는 카운터는 계속 움직인다. 원본 게임의 모든 시간 변수를 정지·복구하는 기능까지 구현한 것은 아니다. 닫은 뒤 시간 기반 동작의 실제 결과는 사용자 확인 전이다.

## 입력 인터럽트와 공유 상태

키보드 인터럽트는 입력 내용·열림/닫힘·다시 그릴 필요만 바꾼다. 화면 그리기·저장·복원·XMS 호출은 이 경로에서 제거했다. 기존 CREDITS 자금 갱신과 WIN/LOSE 요청 처리는 유지했다.

이전 명령 검색은 화면 출력기가 쓰는 `DRAW_TEXT_PTR`을 임시 검색 위치로도 썼다. 화면 출력 도중 키보드가 명령 검색을 실행하면 이 변수를 덮을 수 있어, 명령 검색 위치를 IRQ의 로컬 스택에 보관하도록 바꿨다. 다시 그릴 필요 플래그는 그리기 전에 지워 그리기 도중 도착한 새 입력 요청이 사라지지 않게 했다.

배경 저장의 XMS 할당·이동 성공 판정은 CF 대신 원래 XMS 반환 규약인 `AX=1`을 검사하도록 고쳤다. 일부 행을 저장한 뒤 실패한 경우도 저장 완료로 간주하지 않는다.

## 유지한 부분

- 게임/메뉴 입력 소유자 판정 `module:0240..028A`는 이전 정상 빌드와 바이트가 동일하다. 저장·이름 입력에서 Enter를 원래 처리기로 보내던 조건을 유지한다.
- 타이틀 메뉴 위치(기준점 148), 다섯 항목의 박스 높이, 한글 후크·폰트·메뉴 오버레이는 그대로다.

- 상주 모듈은 2,448바이트(`0x0990`) 그대로이며, 배경용 4 KiB XMS와 한글 비트맵용 10 KiB XMS의 크기도 늘리지 않았다.
- 빌드 직전과 직후 저장 파일 해시가 일치한다.
