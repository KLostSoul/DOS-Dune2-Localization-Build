# 한글 번역문에 달무리 알파벳·숫자·부호 연결

2026-10-25에 한글 문자열 출력 경로에 연결했고, 2026-10-26에는 알파벳·숫자·부호 입력을 별도 FNT·매니페스트에서 공용 HEX로 통합했다. 아래 초기 검사는 제한된 x86 실행과 파일 대조이며, 전체 DOS 게임을 실행한 결과가 아니다.

## 적용 기준

출력할 문자열에 유효한 한글 토큰이 있으면 그 문자열의 알파벳·숫자·부호를 달무리로 그린다. 한글 앞의 영문과 마지막 한글 뒤의 영문도 포함한다. 공백의 전진 폭은 기존 값을 유지한다. 한글이 없는 문자열의 기존 폭·픽셀 경로는 보존한다.

ASCII 문자는 리소스와 RAM에서 계속 **1바이트**다. `%s`, `%d`, `%%`, 문장 분할 부호 `. ! ?`, 멘타트 WSA 파일명과 `*`/`?`, 단축키 `(A)`를 다른 토큰으로 바꾸지 않는다. 서식 함수가 만든 숫자·영문을 포함한 결과 문자열에서 출력 글리프와 폭을 선택한다. 원본 `0000:37AF`를 실행해 `%d`, `%s`, `%%` 치환 결과가 동일함을 확인했다.

한글이 포함된 단축키 문구의 괄호와 영문자도 이번 요청에 따라 달무리로 그린다. 입력 판독은 그대로 ASCII `(A)`를 읽고 기존 키 코드 표를 사용한다. 과거 “단축키 괄호를 원본 FNT로 출력”한 기록은 당시 상태이며, 이번 출력 선택이 후속 변경이다.

`© × ÷ ± ° ® ·` 등 비ASCII 부호 23개는 한글 번역문에서 한글 뒤의 별도 2바이트 토큰 번호를 사용한다. 한글은 기존대로 가나다순으로 정렬하고, 새 음절이 생기면 부호 토큰과 리소스도 같은 빌드에서 다시 배정한다. 전체 토큰 공간은 3,556개이며 부호 23개를 제외한 한글 수용량은 3,533개다. 한글 없는 영문 리소스에는 기존 `© → (C)`, `× → x` 처리를 유지한다.

## 원본 출력 구조와 연결 지점

원본의 서식 처리, 줄바꿈, 문자 순회, 정렬, 드라이버 픽셀 함수와 캐시 복원을 사용한다. 추가한 것은 각 문자열 처리 동안 달무리 영문 글리프를 선택하는 상태다.

| 원본 함수 | 역할 |
|---|---|
| `2326:002F` | 전체 문자열 폭 |
| `29C7:0004` | 공통 문자 출력 |
| `0EED:01B8` | 일반 줄바꿈 |
| `32DD:1893` | 임무·멘타트 설명 분할 |
| `3298:0854` | 고정 간격 출력 |

각 함수의 원래 인자를 복사해 원본 본문으로 전달하고, 원래 반환값과 레지스터 결과를 유지한다. 함수 시작에서 한글 포함 여부를 확인하고 상태를 자기 스택에 저장·복원한다. 고정 간격 출력은 원래 1자 임시 버퍼에서 출력하므로 바깥 문자열의 상태를 안쪽 문자 출력에 전달한다. 호출자의 부모 BP나 반환 주소를 추측해 문자열을 찾지 않는다.

원본 함수의 첫 명령 묶음만 확장 모듈의 진입부로 연결하고, 옮긴 명령을 실행한 뒤 원본 본문으로 복귀한다. 실제 소유 함수의 CS를 보존해 오버레이 코드로 돌아간다. 게임 DS의 원래 논리 세그먼트 `3342h`를 기준으로 확장 세그먼트 `3D02h`를 구하며 새 오버레이 fixup은 추가하지 않는다. 고정 간격 출력의 검증된 구현 진입은 `3D02:1EE0`이며 기존 `2326:0018` 게이트웨이 바이트와 대조한다.

달무리 영문·숫자·부호는 원래 4픽셀 전진 폭에 좌우 여백 1픽셀씩을 더한 6픽셀 셀을 사용하고 기존 스타일 간격을 더한다. 설명 스타일 30h의 테두리와 메뉴 무테두리 규칙은 기존 코드가 결정한다. 출력은 원래 `DS:[66D8]`를 호출하며 원본 드라이버 FNT 캐시 9개 WORD를 복원한다.

오프닝·엔딩 한글은 계속 16×16 유니폰트/XMS 경로다. 같은 문구의 달무리 영문·숫자·부호는 8픽셀 원본을 사용하고 Y를 8픽셀 내려 한글과 아래 기준선을 맞춘다. 이 보정은 기존 달무리 출력기의 유효 Y 계산에서만 적용하며 입력 좌표와 원본 줄 높이를 바꾸지 않는다.

## FNT·빌드 생성

현재 글리프 입력은 `font/composed-hangul.hex` 하나다. 여기에 달무리 8×8 완성 한글 11,172음절과 ASCII·부호 118글리프가 함께 기록돼 있다. 빌드에서는 한글 행만 가나다순 토큰 목록에 넣고, ASCII·비ASCII 부호 행은 달무리 문자 글리프 자료로 읽는다. 원본 고정 부호 33개는 입력 게임 FNT의 슬롯 639~671에 유지하고, 이 33개 비트맵이 공용 HEX와 입력 FNT에서 같은지 확인한다. 나머지 비한글 85글리프는 현재 사용 한글 뒤에 배치한다. 과거 글꼴 FNT와 매니페스트는 생성 입력으로 사용하지 않는다.

빌드가 생성하는 `DUNEHAN.FNT`에는 사용 중인 한글 음절과 비한글 118글리프를 싣는다. 한글은 기존 2바이트 토큰을 사용하고 ASCII는 1바이트를 유지한다. 생성된 FNT는 `import/fnt/DUNEHAN.FNT`에 기록한 다음 그 빌드의 게임 폴더에 같은 바이트로 복사한다.

현재 구현은 `tools/fonts.py`, `import/asm/font/dalmoori-latin-hook.asm`, `tools/translation_data.py`와 `tools/build_game.py`에 통합되어 있다. 새 빌드의 `DUNEHAN.LATIN.csv`에 부호·알파벳·숫자의 실제 슬롯과 입력 코드를 기록한다. 에디터는 빌드 명령을 별도 프로세스로 실행하므로 패치 모듈은 각 빌드에서 새로 읽는다.

## 확인 결과와 범위

다음 4개 검사에서 같은 최종 EXE 해시를 확인했다.

- `check_dalmoori_latin.py`: 공백을 제외한 117글리프 × NEW6P/NEW8P/INTRO 3환경, 351개 폭·픽셀 대조. 원본 printf 실행, 한글 앞뒤 ASCII, 전체 문자열, 고정 간격, 두 줄바꿈 경로, 16픽셀 한글과 8픽셀 영문의 기준선, 상태 복원 및 현재 목록의 단축키 58개 판독을 확인했다.
- `check_dalmuri_two_byte.py`: 734음절의 비트맵·실제 판독/폭/픽셀, 전체 코드 공간의 판독, 정·역방향 이동, 번역 리소스 929개, 내장 가문 이름, 부호 슬롯과 지정 패치 외 오버레이 보존을 확인했다.
- `check_unifont_intro.py`: 사용 음절 152개, 네이티브 FNT·원본 픽셀, XMS 적재/해제/실패 정리와 새 음절 자동 추가를 확인했다. DOS/XMS 서비스는 모형이다.
- `check_subtitle_tokens.py`: 현재 문자표에서 실제 E1h 후행 바이트를 가진 음절의 원본 손상을 재현하고, 오프닝·엔딩·전체 음절·23개 부호 토큰을 포함한 80개 제자리/별도 버퍼 검사를 통과했다. 토가 항상 E6 E1이라는 과거 번호를 가정하지 않는다.

검사는 빌드의 `translation-snapshot`을 읽는다. 에디터에서 현재 CSV가 계속 바뀌어도 검사 입력을 과거·현재 문장으로 섞지 않는다. 검사 모델은 세션이나 CSV를 쓰지 않는다. 결과 파일 경로와 해시는 생성본 `translation-editor-report.json`의 `static_verification`에 기록했다. 실제 게임 화면과 키 입력의 사용자 확인은 아직 받지 않았다.
