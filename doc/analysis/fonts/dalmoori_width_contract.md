# 달무리 폭 콜백과 문자열 포인터 계약

## 원본 폭 조회에서 ES가 가리키는 대상

원본 문자 출력 루프 `29C7:0004`는 `29C7:0098`에서 문자열 문자를 AL에 읽은 뒤, `29C7:009B`에서 ES를 FNT 세그먼트로 바꾼다. 이어 `29C7:00A6`의 `MOV AL,ES:[BX+DI]`로 폭 테이블을 직접 읽는다. 이 원본 단계에는 폭 콜백 호출이 없다. 이때의 `ES:[BX+DI+1]`을 한글 토큰의 다음 바이트로 읽으면 인접한 FNT 폭 데이터를 문자열로 오인하게 된다.

REA로 확인한 기준 호출자 주소는 `0x39C74`이며, `0x39D08`에서 문자열을 읽고 `0x39D0B`에서 ES를 폰트 세그먼트로 바꾼다. 주소는 Ghidra의 로드 세그먼트 1000h를 포함한 선형 주소다.

한글 후크에 추가된 `WidthAtSI`는 [dalmoori-base.asm](../../../import/asm/font/dalmoori-base.asm)에 구현되어 있다. 이 후크는 SI의 문자열 포인터를 `ReadGlyph`에 전달하고, 해석한 글리프의 폭을 `WidthByGlyph`로 구한다. 원본의 폭 테이블 직접 조회와 이 추가 후크의 처리를 구분한다.

## 폭 판정과 토큰 해석의 분리

문자 하나의 폭 조회와 문자열 판독은 서로 다른 입력 계약을 갖는다. 문자열 포인터가 없는 폭 콜백에서 후행 바이트를 추측하지 않는다. 실제 문자열 포인터가 있는 전체 폭 계산·정방향 및 역방향 이동·그리기 경로에서만 토큰을 해석한다.

현재 빌드는 `tools/fonts.py`가 생성하는 `Reader`에서 유효한 2바이트 토큰을 물리 글리프 슬롯과 소비 길이로 변환한다. 각 순회 함수가 이 길이로 자기 포인터와 카운터를 갱신한다. 폭 선택은 `NewWidth`와 달무리 문자 선택을 거치며 한글 10픽셀 셀, 달무리 영문·숫자·부호 6픽셀 셀에 원래 문자 간격을 더한다. 영상 한글과 수집 부호는 Unifont의 폭을 적용한다.

문자열에 한글이 포함된 경우의 달무리 영문·부호 선택은 [출력 선택](dalmoori_latin_symbols.md), 토큰 범위와 FNT 생성은 [폰트 규약](../../FONTS.md#2바이트-토큰과-출력-규약)을 따른다.

## 메모리와 검사

달무리 글리프는 HEX에서 완성 FNT로 생성한 뒤 EXE 상주 이미지에 포함한다. 글리프 수에 따라 치트 모듈·스택·재배치를 함께 계산한다. 영상 Unifont와 치트 배경의 XMS 수명은 [메모리 배치](../../FONTS.md#메모리-배치)를 따른다.

`python tools/check_final_build.py --only hangul latin unifont`는 토큰 경계·글리프·폭·캐시 복원과 영상 출력 경로를 검사한다. 실행 중 여유 메모리는 생성 이미지의 크기만으로 확정하지 않고 MCB·힙 상태와 함께 판정한다.
