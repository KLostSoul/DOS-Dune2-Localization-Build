## 확인한 오류

원본 출력 호출자의 폭 계산 단계에서 ES는 문자열이 아닌 원본 FNT를 가리킨다. 원본 호출자는 문자열 문자를 AL에 읽은 뒤 ES를 FNT 세그먼트로 바꾸고 폭 콜백을 호출한다. 실패 후보는 이 단계의 `ES:[BX+DI+1]`을 한글 토큰의 다음 바이트로 읽었다. 실제로는 인접한 FNT 폭 데이터여서 한글 폭 판정이 잘못될 수 있었다.

REA로 확인한 기준 호출자 주소는 `0x39C74`이며, `0x39D08`에서 문자열을 읽고 `0x39D0B`에서 ES를 폰트 세그먼트로 바꾼다. 주소는 Ghidra의 로드 세그먼트 1000h를 포함한 선형 주소다.

근거: `ev_1bbc826e69cac7ba2bf84da92ed4954d2021772916d51ef545bdc4bb07066f1f`.

## 재작성 내용

- 폭 콜백은 검증본처럼 AL의 한글 선행 바이트를 판별하여 10픽셀을 반환한다. FNT 폭 표에서 토큰 후행 바이트를 읽지 않는다.
- 실제 문자열이 전달되는 그리기와 문자열 폭 계산 경로에서만 두 바이트 토큰을 해석한다.
- 새 공통 DecodeToken은 F8/F9/FB/FC/FD/FE 선행 바이트와 유효 후행 바이트를 0~638 인덱스로 바꾼다. 제어 문자 LF/CR/ESC와 범위 밖 인덱스를 제외한다.
- 기존 영문과 부호는 원본 FNT 출력 경로를 사용한다.
- 달무리 비트맵은 `font/composed-hangul.hex`에서 다시 생성했다. 639개 완성 음절, 파일 6,414바이트다. 글리프는 8×8이며 셀 폭은 좌우 여백을 포함해 10픽셀이다.
- 기존 번역을 새 한글표 토큰으로 적용했다. 기준 메뉴의 다섯 한글 항목도 새 토큰으로 다시 인코딩했다.
- 치트 코드는 검증본을 유지하고 위치 이동에 필요한 세그먼트 상수 두 개를 바꿔 재조립했다.
