# 영상 자막의 Unifont FNT와 XMS 출력

오프닝·엔딩·황제 영상에서 사용하는 한글과 문장 부호를 `font/unifont-16.0.04.hex`에서 수집해 네이티브 Westwood FNT와 위치표로 생성한다. 사용하지 않는 전체 한글 음절을 게임에 적재하지 않는다.

## 수집 범위와 파일

`INTRO.ENG` 1~19는 오프닝, 20~24는 아트레이데스 엔딩, 25~31은 하코넨 엔딩, 32~37은 오르도스 엔딩이다. 황제 영상은 `DUNE.ENG` 287~292, 293~297, 298~303, 304~308, 309~314, 315~320을 사용한다. 이 범위에서 한글과 유니코드 문장 부호·기호를 수집한다.

한글은 공통 가나다순 토큰 번호를 공유한다. 번역에 새 음절이 생기면 달무리·유니폰트의 대응표와 문자열을 같은 빌드에서 생성한다. `DUNEUNI.FNT`는 16×16·4bpp FNT이며 256슬롯을 넘으면 `DUNEUN1.FNT` 등으로 나눈다. `DUNEUNI.MAP`은 공통 번호를 XMS의 글리프 위치에 대응시키는 DWORD 표다. 생성 파일은 `import/fnt/`를 거쳐 게임에 적용된다.

## 원본 폰트 선택과 픽셀 출력

활성 FNT의 헤더 길이 `1C24h`, 버전 `0500h`, 높이/폭 `19/17`로 원본 INTRO.FNT를 판별한다. 한글은 16픽셀 폭에 원래 간격을 더한다. 번역문에 포함된 달무리 영문·숫자·부호의 선택은 별도 [달무리 출력 규칙](dalmoori_latin_symbols.md)을 따른다.

엔딩의 `32AE`는 공통 애니메이션 초기화 `32F0:0020`을 호출한다. 실제 초기화 코드 `00B2`가 INTRO.FNT를 로드하고 `00CC`가 선택한다. 황제 영상의 `32B1`도 같은 초기화기를 사용한다.

한 글자를 그릴 때만 임시 1슬롯 FNT를 연결해 원래 드라이버 `DS:[66D8]`를 호출하고 캐시 9개 WORD를 복원한다. 원래 문자열 순회·분할·음성 호출은 유지한다.

## XMS 수명

FNT와 위치표를 256바이트씩 읽어 XMS로 전송한다. 요청 크기는 실제 데이터와 짝수 전송용 패딩을 포함해 KiB 단위로 올림한다. 글자 출력 시 위치표 4바이트와 4bpp 글리프 128바이트를 가져온다.

상주 영역에는 코드·파일 목록·이동 구조체·257바이트 전송 버퍼·153바이트 임시 FNT 버퍼만 둔다. 전체 비트맵과 색인표를 상주 이미지에 중복 저장하지 않는다. 일반 폰트로 돌아갈 때 핸들을 해제하고 다시 필요하면 적재한다. XMS·파일 오류에서는 열린 파일과 핸들을 정리한 뒤 달무리 경로로 복귀한다. 별도 DOS 블록과 게임 FAR 힙 할당은 없다.

## 자막 전처리와 2바이트 토큰

원본 `32F0:0CB5` 전처리는 단일 바이트 E1h를 01h로 바꾼다. 한글 토큰의 후행 E1h까지 바꾸면 `E6 E1` 같은 유효 토큰이 `E6 01`로 손상된다. 전처리는 선행·후행 범위를 판별해 유효 토큰 두 바이트를 함께 복사하고, 토큰 밖의 단일 E1h 변환만 유지한다. 특정 음절 하나를 예외 처리하는 방식은 아니다.

구현은 `tools/fonts.py`, `tools/scenes.py`, `import/asm/font/unifont-intro-hook.asm`, `import/asm/scene/subtitle-normalize.asm`이다. 검사는 원본 HEX와 FNT 재판독·출력 픽셀·캐시 복원·다중 페이지·적재 실패 정리를 포함한다.
