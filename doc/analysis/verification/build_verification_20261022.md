# 현재 빌드와 누적 확인 결과 — 2026-10-22

이 문서는 현재 실행 대상과 지금까지의 주요 확인 결과를 모은 최신 기준점이다. 개별 문서의 ‘현재 빌드’·‘확인 전’은 작성 당시의 이력이므로, 아래 최신 상태와 함께 읽는다. 현재 실행 후보에서 영어 오프닝 자막과 음성이 함께 정상 출력되는 것을 사용자가 확인했다.

이후 확인된 CG 편집 범위·코덱 검증·가문 질문 세 줄 출력·사용자 정상 보고·편집용 PNG 채택은 [CG 누적 확인 결과](graphics_verification_20261022.md)와 아래 10절에 추가했다. 일반 실행 배치의 빌드와 사용자 정상 확인을 받은 별도 CG 시험 빌드를 구분한다.

## 3. 폰트·원본 엔진 유지 원칙과 현재 구성

- 한글은 필요한 완성 음절 639개를 달무리 8×8 비트맵으로 저장한다. 조합 글리프 사용 후보와 혼동하지 않는다.
- 달무리 TTF에서 추출한 부호 33개를 추가해 FNT 저장 글리프는 672개다. 기존 한글 639개는 그대로 유지했다.
- 한글 토큰은 기존 2바이트 방식이다. 원본 영문·숫자 FNT, 원본 문자열 포맷·폭 계산·문자 루프·픽셀 출력 호출 구조를 유지한다.
- ASCII 괄호 28h/29h는 원본 듄 FNT로 출력하며 폭도 원본 값을 사용한다. 다른 달무리 부호는 유지한다.
- 설명용 스타일 30h는 테두리, 메뉴 스타일 10h/20h는 무테두리다. 명예의 전당 제목·열 제목·기록 이름 문자열에는 30h를 지정했다.
- 메뉴 영문에 테두리가 남았던 이유는 한글 테두리 판별과 달리 원본 FNT의 가장자리 픽셀이 20h의 0Ch/00h 색 매핑에서도 표시됐기 때문이다. `0EED:1F3D`의 20h 가장자리 색을 00h/00h로 바꿨다. 메뉴 박스 테두리를 없앤 것이 아니다.

## 4. 배치·간격 수정과 실수 원인

- 게임 메뉴 선택문은 원래 위치보다 아래 2픽셀. 프레임과 마우스 사각형을 이동시킨 변경이 아니다.
- 짧은 멘타트 그림 설명은 원본 8픽셀 피치를 11로 조정했다. 설명 테두리 포함 높이 10 아래에 1픽셀을 남긴다.
- 멘타트 목록은 브리핑 첫 표시 행을 상대 Y=16에 유지한다. 이후 대주제마다 2픽셀, 소주제마다 1픽셀을 누적한다. 표시 행은 9개이며 스크롤·페이지 이동·끝 경계 및 위젯 좌표를 맞췄다.
- 브리핑이 위로 붙었던 원인은 생성 ID 2의 Y=8을 실제 첫 표시 ID 3의 Y=16과 혼동한 것이다. 기준 좌표를 복구하고 첫 행 앞에는 추가 공백을 누적하지 않도록 수정했다.
- 임무 선택 지도 설명의 가로 간격은 -2→-1. 기존 색·좌표를 유지하고 전용 옵션 비트 8000h로 범위를 구분한다.
- 게임 상단 메시지의 가로 간격도 -2→-1, 두 표시 행 Y는 2/13→3/14다. 마지막 요청 이후 별도의 정상 보고가 없는 세부 항목까지 실행 확인 완료라고 확대하지 않는다.

## 5. EXE 내장 가문 이름

`Atreides 삼륜차.`는 원문 가문 이름과 번역된 유닛 이름을 서로 다른 곳에서 읽어 합친 결과였다. 내장 이름은 가문 정보표 `3342:37EC + ID×30`에서 읽는다. 이 이름의 첫 글자를 리소스 파일 식별에도 쓰므로 원문 이름을 제자리에서 한글로 덮어쓰지 않았다.

표시 이름은 하코넨·아트레이아스·오르도스·프레멘·사다우카·용병이다. `translation/executable_house_names.csv`와 기존 실행 파일 문자열 검토 CSV에 등록하고 유닛 선택·유닛/건물 문맥 메시지의 5개 조회 경계에 연결했다. 원문 식별 이름과 포인터 표는 보존했다. 명예의 전당의 별도 이름 조합 등 모든 가문 이름 참조를 일괄 교체했다고 기록하지 않는다.

## 6. 단축키 처리 경로와 누락 원인

### 공통 위젯

원본은 표시 문자열 첫 바이트를 `27DE:00DA`에 넘겨 키를 등록했다. 한글 대체 후 첫 바이트가 영문 A/M 등이 아니므로 연결이 깨졌다. 한글 문자열 끝의 `(A)` 등을 읽어 기존 키 표로 넘기도록 수정했다. 기존 위젯·명령 실행 경로와 고정 키는 유지한다. 소문자/대문자는 원본 키 표에서 같은 키 코드에 대응하며 현재 표기는 대문자로 통일했다.

### 타이틀 목록

별도 `32E9:0200` 입력 함수는 공통 위젯 키 변환기를 거치지 않고 문자열 첫 바이트와 키 입력을 `0000:10C3`의 대문자 변환으로 비교했다. 그래서 공통 수정만으로 타이틀 P/R/L/E/H가 복구되지 않았다. `32E9:03C8`, `03DD`의 두 비교 입력을 접미사 지원 키 변환기로 연결했다. 기존 오버레이 fixup 슬롯을 재사용했다.

## 7. 메모리와 설정에서 확정한 범위

현재 확장 모듈 시작은 파일 41C20h, 세그먼트 3D02h다. 부호 추가 때 모듈 크기가 7,568→8,144바이트로 증가했고 치트 세그먼트는 3EFFh, 스택 기준은 3F98h로 이동했다. 현재 MZ 끝은 44580h이다. 이후 목록·간격·가문 이름·단축키 수정은 기존 빈 코드/데이터 공간과 MZ 헤더 재배치 슬롯을 사용했으며 파일의 상주 이미지 크기를 추가로 늘리지 않았다. 별도 DOS 폰트 블록·FAR 힙·추가 XMS 요청을 새로 만들지 않았다.

과거 사용자가 제공한 MCB의 free 45,872바이트는 해당 캡처 시점의 실측이다. 현재 빌드의 모든 게임 상태에서 같은 여유가 남는다는 측정값으로 사용하지 않는다. 과거 lose 치트 정상 진행·폰트 및 치트 정상 작동 보고는 기존 메모리/치트 문서의 해당 빌드 이력에 속한다. 새 수정 때마다 전체 미션·모든 메모리 상태를 다시 확인했다고 주장하지 않는다.

실제 DOS 목표와 DOSBox-X 설정을 혼동하지 않는다. 위 설정은 현재 실행 배치가 사용하는 에뮬레이터 설정이다.

## 8. 멘타트 리소스 정지·노이즈 재발 방지

원본 읽기·압축 해제·출력 순서를 지켜야 한다. NAME/DESC 길이나 위치뿐 아니라 INFO의 저장 최대 길이와 중간 압축 해제 최대 길이도 번역된 데이터에서 NUL까지 포함해 계산해야 한다. 하코넨 설명의 노이즈는 329바이트 설명에 원문 읽기 제한 209를 유지하여 끝 NUL이 들어오지 않은 것이 원인이었다. INFO 최대 읽기/전개 길이를 재계산했고 기존 포장기에 반영했다.

관련 문서: [멘타트 INFO 오류](../engine/mentat_info_length.md), [원본 구조 보존](../engine/native_output_rebuild.md).

## 9. 이후 작업 기준

- 현재 실행 배치와 이 문서의 빌드·해시를 먼저 확인한다. 다른 과거 후보를 최종 성공 빌드라고 바꿔 부르지 않는다.
- 기존 정상 빌드를 보존하고 사용자 요청 범위만 수정한다. 폐기한 후보를 성공 기준으로 재사용하지 않는다.
- 기존 문서와 원본 코드·실제 문자열 ID를 확인한 뒤 수정한다. 영문 이름이 같다는 이유로 ID를 하나로 합치지 않는다.
- 기존 FNT·원본 출력 구조·게임 입력 흐름을 유지한다. 한글·CG·식별 문자열·단축키 메타데이터를 구분한다.
- 게임 실행 확인은 사용자가 수행한다. 빌더의 바이트 대조·정적 근거를 실제 게임 확인으로 표현하지 않는다.
- 새로운 실행 오류가 발견됐다고 근거 없이 말하지 않는다. 사용자 정상 확인의 범위와 아직 개별 보고가 없는 범위를 정확히 기록한다.

## 10. 후속 CG 편집·가문 질문 확인 결과

### 편집 프로젝트와 원본 PAK 범위

사용자 지시에 따라 `cg/editable/images/DUNE`은 CHOAM.CPS·MAPMACH.CPS·SCREEN.CPS만 유지했다. FRENCH·GERMAN·FINALE·MENTAT·INTRO의 편집 폴더와 관련 리소스를 제외했다. `original`의 비활성 PAK와 매니페스트 항목도 정리하여, 현재 편집 프로젝트와 재인코딩 출력에는 **DUNE.PAK·ENGLISH.PAK 두 개**만 포함한다.

## 11. 번역 에디터의 기호 검사·크레딧 종료 데이터 수정

2026-10-22 사용자가 보고한 TEXTH.ENG #7·TEXTO.ENG #7의 `×`, CREDITS.ENG #117·#119의 `©`, #149의 충돌 오류를 코드와 CSV 및 현재 게임 자산에서 대조했다.

- 기존 리소스 빌더 `target_translation()`은 `×`를 `x`, `©`를 `(C)`로 바꾸지만 에디터 `Model.encode()`에는 이 처리가 빠져 있었다. 에디터 인코딩에도 두 변환을 추가했다. CSV와 편집 화면의 원문은 바꾸지 않고 게임 바이트를 생성할 때만 변환한다.
- #149의 원문은 물음표가 아닌 U+0000이며, 게임의 해당 크레딧 행도 실제 `00` 바이트다. 일반 문자열 검증에서 제외하고 재구축 시 원본 `00`을 그대로 보존한다. 종료 데이터에 번역이 입력되거나 원본 행이 달라지면 오류로 막는다. 다른 문자열의 NUL 금지는 유지한다.
- 일반 물음표 `?`는 ASCII `3F`이며 NEW6P·NEW8P 양쪽에 정상 글리프가 있다. 앞서 물음표 충돌로 해석했던 설명을 정정한다.

수정 파일은 `tools/translation_editor/model.py`다. 저장된 CSV·폰트·검증된 게임 빌드·실행 배치는 변경하지 않았다. 이번 수정에서 게임 실행이나 새 빌드 생성은 하지 않았다.

## 12. 오프닝 영어 자막 정적 분석

REA/Ghidra에서 영어만 피드백 항목의 문자열 ID가 0일 때 자막 그리기를 건너뛰는 것을 확인했다. 앞선 후보의 `3208:6CC0` 무조건 분기 수정은 피드백 호출까지 생략했고, 사용자는 그 후보에서 자막이 표시되는 것을 확인했다. 음성 재생 여부는 확인된 바 없다.

현재 빌드는 기준 실행본을 새로 복사해 `3208:6CE2`, 파일 오프셋 `0x54051`의 `JZ` (`74 20`)만 `NOP NOP` (`90 90`)으로 바꿨다. 언어 분기 `3208:6CC0`와 피드백 호출 `3208:6CCD`는 그대로라서 조회 흐름을 보존한 채 누락 자막도 기존 문자열 조회·그리기 경로로 이어진다. EXE 크기는 382,066바이트로 같고 실행 메모리 배치 변경은 없다. 사용자가 이 빌드에서 영어 자막과 음성이 함께 정상 출력된다고 확인했다. 상세 주소, 해시 및 근거 파일은 [오프닝 영어 자막 정적 분석](../engine/english_subtitles.md)에 기록했다.
