# 멘타트 INFO의 읽기 길이와 버퍼 경계

멘타트 리소스는 청크 위치뿐 아니라 INFO에 저장된 최대 읽기·전개 길이도 사용한다. 번역으로 본문이 길어지면 INFO도 함께 재계산해야 한다.

## 길이 불일치의 영향

`MENTATA.ENG` 5번의 `FHARK.WSA*Giedi Prime: ...` 항목은 한글 저장 크기가 NUL 포함 329바이트인 분석 표본에서 INFO 읽기 길이가 209바이트였다. 이 상태에서는 문자열 끝 NUL이 입력 버퍼에 들어오지 않는다. 원본 해제기가 버퍼의 이전 내용까지 읽어 글자 노이즈나 다른 설명이 섞일 수 있다.

## 원본 읽기 순서

| 주소 | 처리 |
|---|---|
| `32E3:0616..062B` | INFO 12바이트를 지역 버퍼에 읽기 |
| `32E3:064D..065D` | INFO+8 DWORD의 바이트 순서 변환 |
| `32E3:06A8..06B5` | 해당 값을 파일 읽기 길이로 전달 |
| `32E3:06BD..06CE` | `2307:00F4`로 쌍 압축 해제 |
| `32E3:06D1..06E2` | `2307:0002`로 ESC 고위 바이트 해제 |

이 처리는 문자 출력 함수보다 먼저 실행된다. 입력 버퍼는 `GetBuffer(3)`의 결과다. INFO+4의 최대 전개 길이를 버퍼 주소 오프셋으로 해석하면 안 된다.

## 재계산 규칙

세 멘타트 리소스의 INFO 페이로드 12바이트에 최대 저장·전개 길이를 기록한다. 두 해제 단계의 결과를 각각 계산하고 NUL까지 포함한다. ESC로 저장된 고위 바이트 때문에 중간 결과가 최종 토큰 문자열보다 클 수 있다.

분석 표본의 최대 전개/읽기 길이는 MENTATA 392/392, MENTATH 449/449, MENTATO 365/365바이트다. 고정 상수로 사용하지 않고 번역 데이터로부터 계산한다. 글리프나 실행 코드의 변경 없이 리소스 메타데이터로 해결하는 경계 문제다.
