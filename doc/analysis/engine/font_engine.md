# 원본 FNT 엔진의 조회·배치·픽셀 출력 계약

## 전체 호출 구조

```text
화면/대화상자 코드
  ├─ 0EED:1E65  폰트·색·간격·정렬 설정 및 문자열 포맷
  │    ├─ 2326:002F  문자열 전체 폭 계산
  │    │    └─ 2326:0009  글자별 폭 조회
  │    └─ 29C7:0004  문자 단위 순회·개행·줄바꿈·화면 경계 처리
  │         ├─ DS:[675C] → 20AA:110C  문자열별 색상 인덱스 0·1 적용
  │         └─ DS:[66D8] → 20AA:07BD  FNT 글리프 픽셀 출력
  │              ├─ 20AA:0E02  활성 화면 페이지 선택
  │              └─ CS:0091  색 변환표 (스타일 콜백이 설정)
  └─ 폰트 전환
       ├─ 2371:000E  FNT 파일 읽기·메모리 적재
       ├─ 240A:0006  게임 공통 폰트 포인터·메트릭 갱신
       └─ DS:[66DC] → 20AA:090C  그래픽 드라이버의 FNT 메타데이터 갱신
```

텍스트 색상 변환표는 두 단계로 설정된다. 공통 출력 함수가 16바이트 스타일 표를 전달하는 경로는 `0EED:1E65` → `23A3:001B` → `3342:[675C]` → `20AA:110C`이고, 문자 루프는 매 문자열 호출에서 두 색상 값을 같은 콜백에 전달해 색상 인덱스 0·1을 덮어쓴다.

`29C7:0004`의 글리프 출력은 함수 포인터다. 원본 데이터 세그먼트 `3342`의 `66D8`에는 `20AA:07BD`, `66DC`에는 `20AA:090C`, `675C`에는 색 변환 콜백 `20AA:110C`가 저장돼 있다. `29C7:0004`는 한 문자열의 색상 인자를 `675C`에 전달한 뒤 글리프마다 `66D8`을 호출한다. 공통 폰트 선택 `240A:0006`은 FNT 헤더 정보를 `66DC`에 전달한다.

## 문자열표 그룹 선택과 조회

텍스트 출력의 입력은 한 문자열표에서만 오지 않는다. 원본 코드에는 활성 문자열표 그룹을 전환하는 함수 `0DD4:000D`, 인덱스를 문자열 FAR 포인터로 바꾸는 조회 함수 `0DD4:005F`, 그리고 선택 언어 이름을 붙여 리소스 이름을 만드는 함수 `044B:075D`가 있다.

`0DD4:000D`는 기존 문자열표 포인터 `DS:[38BE:38C0]`가 유효하면 `21E5:01CC`로 메모리를 해제하고 두 워드 값을 0으로 만든다. 새 FAR 이름이 널이 아니면 `044B:075D`로 그룹 이름을 구성하고 `2341:0094`에 넘겨 리소스 데이터를 읽은 뒤 새 FAR 포인터를 `DS:[38BE:38C0]`에 저장한다. 이 함수가 직접 받는 인자와 호출 위치는 다음과 같다.

| 호출 위치 | 넘기는 인자 | 확인된 동작 |
|---|---|---|
| `044B:00E5` | `DS:31E8`, 문자열 `DUNE` | DUNE 그룹 선택 |
| `2CA0:26F3` | `DS:1C14`, 문자열 `INTRO` | INTRO 그룹 선택 |
| `31F7:0754` | `DS:230B`, 문자열 `DUNE` | DUNE 그룹 선택 |
| `32F0:0037` | `DS:239E`, 문자열 `INTRO` | INTRO 그룹 선택 |
| `32F5:005F` | 널 FAR 포인터 | 활성 문자열표 해제 |

`044B:075D`는 입력 그룹 이름을 `DS:830E` 버퍼에 복사하고 `"."` 및 언어 코드 문자열을 붙인다. 언어 코드 표는 `3342:31CC`부터 시작하며 첫 항목은 `ENG`; 선택 인덱스 `DS:[37AA]`로 코드를 고른다. 따라서 첫 항목을 선택한 경우 실제 구성 문자열은 `DUNE.ENG` 또는 `INTRO.ENG`다. 이어지는 `2341:0094`는 해당 이름을 파일 시스템/PAK 계층에 열고 데이터를 메모리에 읽어 FAR 포인터를 반환한다. 이 호출 경로의 바이트는 위의 `0DD4:000D`, `044B:075D`, `2341:0094` 진입점에서 각각 대조했다.

`0DD4:005F`는 활성 문자열표가 없으면 널 포인터를 반환한다. 표가 있으면 인덱스에 2를 곱해 16비트 오프셋을 읽고, 그 오프셋을 표 시작 주소에 더하는 `2307:015F`에 인덱스와 FAR 표 포인터를 넘긴다. 이 파일의 원본 코드는 문자열을 UTF-8이나 다중 바이트 문자로 변환하지 않는다. 반환된 바이트열은 이후 공통 문자 루프에서 FNT 슬롯 인덱스로 처리된다.

## 폰트 파일 로드와 선택

### FNT 적재기 `2371:000E`

원본 파일 오프셋 `0x2831E`가 `2371:000E` 진입점이다.

1. 파일명 FAR 포인터를 받아 파일 시스템/PAK 계층에 조회·열기를 요청한다.
2. 첫 2바이트를 읽어 파일 길이를 확인한다.
3. 메모리 관리 함수 `21E5:000E`에 파일 크기를 전달하고, 할당된 버퍼에 나머지 바이트를 읽는다. 파일 전체를 원래 바이트 그대로 메모리에 보존한다.
4. 핸들을 닫고, 버퍼의 바이트 `+2..+3`이 `00 05`인지 확인한다. 제공된 Westwood FNT 파일의 형식 표식과 일치한다.
5. 성공하면 파일 시작을 가리키는 FAR 포인터를 반환하고 실패하면 널 포인터를 반환한다.

적재기는 문자 코드표를 만들거나 문자를 다른 인덱스로 바꾸지 않는다. 코드 바이트를 FNT의 같은 슬롯 인덱스로 전달한다.

### 일반 폰트 초기화 `23C9:0008`

화면 초기화가 디스플레이 모드와 FAR 폰트 이름을 전달한다. 일반 초기화 함수는 그래픽 모드를 설정하고 `2371:000E`로 해당 FNT를 읽은 뒤 결과 포인터를 전역 기본 폰트에 저장한다. 포인터 오프셋은 `DS:[9A7B]`, 세그먼트는 `DS:[9A7D]`다. 포인터가 유효하면 `240A:0006`에 전달해 문자 폭과 그래픽 드라이버의 폰트 메타데이터를 함께 갱신한다.

원본 FBOV 코드에서 이 초기화 함수로 가는 직접 오버레이 호출은 파일 `0x41ECD`다. 호출 인자는 `DS:[0094]`(오프셋), `DS:[0096]`(세그먼트)의 FAR 포인터이며, 원본 데이터 세그먼트 `3342`의 값은 `3342:00A8`을 가리킨다. `3342:00A8`의 NUL 종료 문자열은 `new8p.fnt`다. 같은 데이터 세그먼트의 `[6D02]` 값 `FFFF`가 모드 인자로 전달된다. 따라서 원본 기본 폰트가 `NEW8P.FNT`라는 것은 정적 인자 추적에서도 확인된다.

### 폰트 전환 `240A:0006`

함수는 새 FAR 폰트 포인터를 저장한다. 오프셋은 `DS:[9A7F]`, 세그먼트는 `DS:[9A81]`이며, 이전 포인터를 반환한다. FNT 파일 헤더의 표 오프셋을 사용해 게임 공통 글꼴 상태를 설정한다.

| 전역 값 | 계산·용도 |
|---|---|
| `[6CFE]`, `[6D00]` | 각각 폭 표 포인터의 오프셋과 세그먼트. FNT 헤더의 폭 표 오프셋을 폰트 주소에 더한다. |
| `[6CFD]` | FNT 정보 블록 `+4`의 최대 높이. 기본 줄 높이와 메뉴 행 간격 계산에 쓰인다. |
| `[6CFC]` | FNT 정보 블록 `+5`의 최대 폭 |
| `[6CF8]` | 문자별 폭에 더하는 수평 간격. 출력 스타일에 따라 `-2`, `-1` 또는 별도 설정값이 들어간다. |
| `[6CFA]` | 줄 높이에 더하는 수직 간격 |

폰트 전환 함수는 그래픽 드라이버의 함수 포인터 `3342:[66DC]`도 호출한다. `20AA:090C`는 전달받은 FNT 포인터와 헤더 오프셋을 그래픽 드라이버의 작업 변수에 복사한다. 드라이버의 `CS:[008A]`(오프셋)와 `CS:[008C]`(세그먼트)는 활성 FNT FAR 포인터이고, `CS:[007C]`, `[007E]`, `[0080]`, `[0082]`, `[0084]`는 차례로 정보 블록·글리프 오프셋 표·폭 표·비트맵 데이터·높이 표의 헤더 오프셋이다. 글리프 출력 콜백 `20AA:07BD`는 활성 FNT를 읽어 글리프 오프셋·폭·높이 정보를 가져오며, 폰트 선택 시 전달된 메타데이터 캐시를 사용한다.

문자열 출력 함수 `0EED:1E65`의 옵션은 `[BP+0x12]`에 있는 16비트 값이다. 하위 니블 비트 `0..3`은 폰트 슬롯을 고른다. `0`은 현재 기본 폰트, `1`은 메뉴 보조 폰트 포인터 `DS:[3A20]`/`DS:[3A22]`, `2`는 저장된 이전 폰트 포인터 `DS:[3A24]`/`DS:[3A26]`다. 마지막 선택값을 캐시해 같은 폰트 설정 호출을 줄인다.

`bits 4..7`은 네 스타일 키 `0x10`, `0x20`, `0x30`, `0x40` 중 하나다. 스타일은 `DS:[6CF8]`의 문자 간격과 `[8B6C]`, `[8B6D]` 두 색 변환값에 반영된다. 실제 코드 흐름에서 `0x10`은 간격 `-2`, 두 값 `0,0`; `0x20`은 `-1`, `0x0C,0`; `0x30`은 `-1`, `0x0C,0x0C`; `0x40`도 분기 뒤 최종값이 `-1`, `0x0C,0`이다. 함수는 `[8B6A]`부터의 16바이트 스타일표를 `23A3:001B`에 넘겨 그래픽 드라이버 표를 갱신한다.

`bits 8..11` 값 `0x100`과 `0x200`은 둘 다 문자열 폭을 계산해 절반만큼 시작 X를 왼쪽으로 옮긴다. 이 옵션을 화면 중앙 정렬의 코드 동작으로 확인했다. 이 플래그는 폰트 슬롯·스타일 니블과 별도다.

### 공통 출력 함수 `0EED:1E65`의 문자열 처리 순서

이 함수 인자는 FAR 포맷 문자열 `[BP+6:8]`, 시작 X `[BP+0x0A]`, Y `[BP+0x0C]`, 스타일 콜백으로 전달할 두 값 `[BP+0x0E:0x10]`, 옵션 `[BP+0x12]`, 그리고 스택에 놓인 가변 인자들로 구성된다. 정적으로 확인되는 처리 순서는 다음과 같다.

1. 옵션의 폰트 슬롯과 스타일을 먼저 적용한다. 따라서 문자열 포인터가 널이어도 폰트·색·간격 상태는 갱신될 수 있다.
2. 문자열 포인터가 유효하면 `0000:37AF`를 호출해 포맷 문자열과 가변 인자를 공용 버퍼 `DS:8B7A`에 전개한다. `37AF`는 출력 버퍼를 비우고 `0000:111F` 포맷 루틴으로 연결한다. 포맷 루틴은 `%` 지시자를 분기표로 해석하고, 80바이트 단위 임시 출력을 `0000:374D` 콜백으로 대상 버퍼에 이어 붙인다. 코드표에는 `%s`, `%d/%i`, `%u`, `%o`, `%x/%X`, `%c`, `%p`, `%e/%f/%g`, `%n` 분기가 있다. 이 단계는 문자열 바이트만 만든다.
3. 옵션에 중앙 정렬 비트 `0x100` 또는 `0x200`이 있으면 `2326:002F`로 버퍼 폭을 재고 절반만큼 X를 왼쪽으로 이동한다.
4. 버퍼 포인터, X/Y, 두 스타일 값을 `29C7:0004`에 전달한다. 문자별 FNT 폭 조회와 픽셀 콜백 호출은 그 문자 루프에서 수행한다.

따라서 가변 인자 치환과 글리프 선택은 별도 단계다. `%s` 치환 뒤에도 결과는 기존 게임 코드 바이트 문자열이다. 2바이트 한글 토큰을 쓸 때는 문자 루프의 1바이트 계약과 폭/글리프 콜백 경계에서 토큰을 한 단위로 소비하도록 한글 후크를 적용해야 한다. 후크 주소와 반환-IP 분기는 [원본 시험본 메뉴 후크 역분석](../ui/menu_hooks.md)에 있다.

### 메뉴와 오프닝의 서로 다른 정적 경로

두 화면의 폰트 로드는 과거 문서에서 혼동했다. FBOV 호출과 파일 포인터를 정적으로 추적하면 다음과 같이 분리된다.

- 메인 메뉴 오버레이 파일 `0x49A7C`는 데이터 세그먼트 `3342:22D0`의 `new6p.fnt`를 적재해 보조 포인터 `DS:[3A20]`(오프셋), `DS:[3A22]`(세그먼트)에 저장한다. 이때 이전 기본 폰트 포인터는 `DS:[3A24]`(오프셋), `DS:[3A26]`(세그먼트)에 보관한다.
- 이전 기본 폰트는 위의 정적 추적대로 `NEW8P.FNT`이며, 메뉴 오버레이는 이를 `[3A24:3A26]`에 보관한다.
- 오프닝 오버레이 파일 `0x50E46`은 `3342:25E6`의 `INTRO.FNT`를 읽고, 파일 `0x50E5C`에서 `240A:0006`으로 즉시 전환한다.

이 EXE에서 FNT 로더를 직접 부르는 위치는 세 곳이다: `23C9:02D5`(일반 초기화 함수가 받은 이름), `31F7:03EB`(`3342:22D0`, `NEW6P.FNT`), `3208:6437`(`3342:25E6`, `INTRO.FNT`). `23C9:0008`을 초기화하는 유일한 호출은 `2A5F:0051`이며 그 이름 포인터는 `3342:00A8`, `NEW8P.FNT`다.

실행 파일 문자열 전체에는 추가로 `NEW10P.FNT`(`3342:445E`)와 `STD3P.FNT`(`3342:4493`)도 들어 있다. 이 이름들은 확인된 세 로더 호출의 인자가 아니다. 분석기는 로더 `2371:000E`, 폰트 선택기 `240A:0006`, 초기화기 `23C9:0008`의 직접 호출뿐 아니라 호출 명령 인자를 제외한 나머지 파일에서 이 세 목적지의 고정 FAR 포인터도 찾았으며, 추가 간접 포인터는 발견하지 않았다. 이 결과는 정적 xref JSON의 `font_loader_pointer_pattern_scan`에 남겼다. 따라서 두 문자열의 존재만으로 실제 적재·선택을 주장하지 않는다.

폰트 선택 함수 `240A:0006`의 10개 FAR 호출도 전부 분류했다. `0EED:1EC5`는 출력 옵션의 폰트 슬롯을 적용하고, `23C9:0328`은 기본 폰트 `[9A7B:9A7D]`를 적용한다. 메뉴는 `2BB7:0006`에서 `[3A20:3A22]` 보조 폰트를, `2BB7:0023`에서 `[3A24:3A26]`에 저장한 이전 기본 폰트를 선택한다. 메뉴 행 출력기 `2BD2`도 `01C0`에서 이전 기본 폰트를, `01E8`에서 보조 폰트를 선택한다. 오프닝은 `3208:644D`, `6E1A`에서 `[80F0:80F2]` 폰트를 선택하고, `3208:FE12`는 기본 폰트를, `FFBB`는 지역 변수에 저장된 FAR 포인터를 선택한다. 이 10개 위치는 정적 xref와 호출 인자를 대조한 결과다.

이에 따라 기존 [엔진·텍스트·CG 분석](engine_text_graphics.md)의 “정적 메뉴 경로는 `INTRO.PAK`의 `INTRO.FNT`를 선택한다”는 문장을 구분해야 한다. `INTRO.FNT` 호출은 오프닝 경로이며, 메뉴 경로는 보조 슬롯 `NEW6P.FNT`와 이전 기본 폰트 `NEW8P.FNT`를 각각 선택하는 코드가 있다.

## 문자열 폭과 문자 배치

### 폭 조회 `2326:0009`

문자 인덱스 바이트 `c`에 대해 `[6CFE:6D00] + c`의 폭 바이트를 읽고 `[6CF8]` 간격을 더한다. 문자의 인코딩이나 유니코드 값은 여기서 해석하지 않는다.

### 문자열 폭 합산 `2326:002F`

문자열 길이를 구하고 바이트를 하나씩 읽어 `2326:0009`의 폭을 합산한다. 정렬, 제목 중앙 배치, 메뉴 박스 폭 사전 계산이 이 함수를 공유한다. 이 함수 자체에는 CR(`0D`) 분기가 없다. 줄바꿈을 처리하는 것은 출력 루프 `29C7:0004`이며, 폭 합산은 글자 코드 바이트마다 폭 조회를 수행한다. 원본은 한 바이트 문자표를 전제로 한다.

### 텍스트 출력 루프 `29C7:0004`

함수는 폰트 선택 함수 `240A:0006`이 설정한 활성 FNT 포인터 `[9A7F:9A81]`를 가져온 뒤 NUL 종료 문자열을 바이트 단위로 처리한다.

- CR(`0D`)을 만나면 시작 X로 돌아가고 `[6CFD] + [6CFA]`만큼 Y를 내린다.
- 일반 바이트는 폭 표에서 전진 폭을 읽고 `[6CF8]`을 더한다.
- 오른쪽 경계를 넘으면 현재 줄의 시작 X로 돌아가 다음 줄로 내린다. Y가 200 이상이 되면 문자열을 끝낸다.
- 화면 안에 들어가는 문자는 글자 코드, X, Y를 `[66D8]` 콜백에 전달하고, 콜백 다음에 X를 폭만큼 전진시킨다.

출력 루프와 폭 함수가 모두 문자를 바이트 하나로 센다. 그래서 2바이트 한글 토큰을 입력하면 조합 한 음절을 두 글자로 폭 계산하거나, 첫 바이트를 FNT 슬롯 인덱스로 넘긴다. 기존 메뉴 후크 분석의 2바이트 토큰 소비 수정은 바로 이 원본 단일 바이트 계약을 우회하는 작업이다.

## 단일 글리프 픽셀 렌더러

`20AA:07BD`는 콜백으로 받은 코드 인덱스를 `CS:[008A]`/`CS:[008C]`가 가리키는 활성 FNT에서 해석한다. 글리프 오프셋 표, 폭 표, 높이 표와 정보 블록 오프셋은 위 메타데이터 콜백이 캐시한 값을 사용한다.

1. 오프셋 표에서 글리프 비트맵 시작 위치를 읽는다. 표 값이 0이면 그 슬롯은 그리지 않는다.
2. 폭 표에서 픽셀 폭을 읽고, 높이 표의 두 바이트에서 Y 오프셋과 실제 글리프 높이를 읽는다. FNT 정보 블록의 최대 높이 안에서 위·아래 위치를 계산한다.
3. X와 Y, 글리프 폭·높이가 320×200 작업 화면 경계 안에 있는지 확인한다.
4. `20AA:0E02`를 불러 현재 활성 화면 페이지를 고른다. 고정 A000 세그먼트에 직접 그리지 않는다.
5. 픽셀 데이터는 행 단위 4bpp packed 니블이다. 왼쪽 픽셀은 낮은 니블, 다음 픽셀은 높은 니블이다. 두 니블은 `CS:0091` XLAT 표의 인덱스가 된다. 결과가 0이면 픽셀을 쓰지 않고, 0이 아니면 선택된 화면 페이지에 쓴다.

`CS:0091` 변환표는 스타일 콜백 `20AA:110C`가 채운다. 콜백의 인자는 원본 FAR 바이트열과 적용할 인덱스의 시작·끝이며, 인덱스 양 끝의 하위 니블을 사용한다. `23A3:001B`는 시작 0·끝 15와 `[8B6A]`의 16바이트 스타일 표를 전달해 전체 변환표를 갱신한다. 반면 문자 루프 `29C7:0004`는 `[BP+0E]`, `[BP+10]`의 두 출력 스타일 인자를 각각 `CS:0003`, `CS:0002`에 저장하고, `CS:0002` 바이트열과 인덱스 0..1을 같은 콜백에 전달한다. 두 항목 적용은 `CS:[0091]`에 두 번, `[0092]`와 `[00A1]`에 각각 한 번 쓴다. 즉 낮은 니블의 0·1과 높은 니블의 0·1에 대응하는 표를 출력별 값으로 덮어쓴다. 글리프 출력기 `20AA:07BD`는 이 표를 적용한 뒤에만 화면 페이지에 픽셀을 기록한다.

별도 BIOS 문자 출력 경로 여부도 정적으로 확인했다. 재구성된 코드 구간에서 `CD 10` 명령 바이트는 `31F7:02BF` 한 곳이며, 명령 경계에서 재디코드된다. 바로 앞에서 `AX=1012h`, `BX=0`, `CX=256`, `ES:DX=[3C26]`을 설정하고 있어 팔레트 자료 전달 경로다. 이 실행 파일의 확인 가능한 FNT 문자 그리기는 위 콜백 경로로 이어진다.

색상 변환표와 특정 한글 글리프의 픽셀 분포는 이전 완성 글리프 시험에서 측정한 값이므로 이 원본 엔진 문서에서 일반 규칙으로 확장하지 않는다. 조합형 비교 구현의 콜백 연결은 [조합 FNT 규약](../fonts/composed_hangul_fnt.md)과 [16×16 셀 설계](../fonts/hangul_16x16_design.md)에 설명한다.

## 전체 실행 파일의 직접 호출 목록

정적 분석기는 원본 EXE 전체에서 FAR CALL의 정확한 명령 바이트를 찾고, 발견 위치에서 Capstone 16비트 디코더로 호출 피연산자를 확인한다. 오버레이는 세그먼트 표 인덱스×8 형식으로 호출하므로 FBOV 표를 해석해 목표 주소와 맞췄다. 오버레이의 모든 함수 경계를 재구성한 제어 흐름 그래프는 아니므로, 목록은 이 원본 EXE에서 확인된 직접 호출 인코딩의 정적 인벤토리로 읽는다.

| 경로 | 함수 주소 | 발견 호출 수 | 상주 코드 | 오버레이 |
|---|---|---:|---:|---:|
| 폰트 설정·문자열 포맷 | `0EED:1E65` | 76 | 4 | 72 |
| 문자 순회·글리프 콜백 | `29C7:0004` | 8 | 3 | 5 |
| 문자열 폭 합산 | `2326:002F` | 22 | 2 | 20 |
| 문자 폭 조회 | `2326:0009` | 2 | 2 | 0 |
| FNT 파일 적재 | `2371:000E` | 3 | 1 | 2 |
| 폰트 메타데이터 선택 | `240A:0006` | 10 | 2 | 8 |
| 그래픽 모드·기본 폰트 초기화 | `23C9:0008` | 1 | 0 | 1 |

문자 폭 조회는 문자열 폭 합산 내부에서 near call로 한 번 더 쓰인다. 활성 화면 페이지 선택 함수 `20AA:0E02`의 8개 near 호출은 `20AA:07A8, 086B, 0960, 0BD1, 0CFC, 0D4D, 0E66, 0FA9`이며, `086B`는 글리프 렌더러의 페이지 선택이다. 글리프 출력은 `29C7:0004`의 `3342:[66D8]` 간접 호출이고, 폰트 메타데이터 설정은 `240A:0006`의 `3342:[66DC]` 간접 호출이다. JSON에는 각 직접 FAR CALL의 파일 오프셋, 상주 세그먼트 또는 오버레이 인덱스, 명령 바이트 디코딩 결과를 보존했다.

### 호출부 분류 보완

위 표의 `0EED:1E65` 76회는 FAR CALL 인코딩만 센 수였다. `0EED` 코드 세그먼트 안에서 같은 포맷 함수를 부르는 14개의 near CALL도 별도로 찾아 디스어셈블했다. 따라서 지정된 원본 EXE에서 확인한 포맷 함수 호출 인코딩은 합계 90개( FAR 76, near 14 )다. near 호출은 모두 `PUSH CS; CALL rel16` 문맥과 포맷 함수의 반환 후 스택 정리를 확인했다.

| 기능 | FAR 참조 | near 참조 | 간접 참조 |
|---|---:|---:|---:|
| 문자열표 그룹 선택·해제 | 5 | 0 | 0 |
| 문자열표 조회 | 114 | 0 | 0 |
| 문자열 버퍼 변환 헬퍼 | 3 | 0 | 0 |
| 공통 포맷·텍스트 출력 | 76 | 14 | 0 |
| 문자 순회·글리프 콜백 경로 | 8 | 0 | 2 dispatch sites |
| 문자열 폭 합산 | 22 | 0 | 0 |
| 문자 폭 조회 | 2 | 1 | 0 |
| 활성 화면 페이지 선택 `20AA:0E02` | 0 | 8 | 0 |
| FNT 파일 적재 | 3 | 0 | 0 |
| 폰트 정보·메타데이터 선택 | 10 | 0 | 1 dispatch site |
| 글리프 색 변환표 콜백 `20AA:110C` | 0 | 0 | 2 dispatch sites |
| 그래픽 모드·기본 폰트 초기화 | 1 | 0 | 0 |
| 포맷 대화상자 헬퍼 `0EED:0273` | 6 | 1 | 0 |
| 상태 메시지 대기열 헬퍼 `0EED:09AB` | 26 | 0 | 0 |
| 게임 정보 패널 헬퍼 `0EED:0F1A` | 8 | 1 | 0 |

간접 참조 슬롯은 세 개지만 디스패치 명령은 네 곳이다. `3342:[66D8]`는 문자 루프의 글리프 출력(`29C7:00D4`), `[66DC]`는 폰트 메타데이터 설정(`240A:006E`), `[675C]`는 전체 스타일 표 설정(`23A3:0030`)과 문자열별 두 색 값 적용(`29C7:0075`)에 쓰인다. 분석기가 네 호출의 명령 경계·간접 호출 형태·슬롯 주소를 재검증하고, 직접 슬롯 참조 전수와 대조한다. 결과는 JSON의 `renderer_dispatch_audit`와 `renderer_dispatch_sites`에 있다.

| 디스패치 명령 | 슬롯 → 목적지 | 전달 데이터와 용도 |
|---|---|---|
| `240A:006E` | `[66DC]` → `20AA:090C` | 선택한 FAR FNT와 헤더 표 오프셋을 활성 폰트 메타데이터로 설정 |
| `23A3:0030` | `[675C]` → `20AA:110C` | `[8B6A]`의 16바이트 표와 인덱스 범위 `0..15` 전달 |
| `29C7:0075` | `[675C]` → `20AA:110C` | 출력별 두 스타일 바이트와 인덱스 범위 `0..1` 전달 |
| `29C7:00D4` | `[66D8]` → `20AA:07BD` | 현재 문자열 코드 바이트와 계산된 X/Y로 글리프 한 개 출력 |

문자열 버퍼 변환 헬퍼 `0DD4:0088`도 별도 분류했다. 직접 호출은 `3208:515F`, `3208:BA16`, `3208:BF6D` 세 곳이다. 함수 본문은 FAR 문자열 포인터와 위치·길이 인자를 검사한 뒤 런타임 문자열/메모리 함수(`1DB7:0202`, `120F`, `0AF4`, `09CF`, `2913:0000`, `2307:00F4`)를 호출하고 결과 포인터를 반환한다. 본문에는 FNT 상태 전역 참조, 포맷 출력 함수, 문자 루프 또는 글리프 콜백 호출이 없다. 그러므로 세 지점은 문자열 데이터 변환 호출이며, FNT 출력 호출 수에 더하지 않았다. 호출자에서 변환 결과가 어느 화면에서 실제로 출력되는지는 이 헬퍼의 직접 호출만으로 단정하지 않는다.

원본 EXE 안에서 확인한 엔진 직접 FAR 호출 284개와 near 호출 25개를 코드 범위 안에서 재디코드했다. 각 호출은 가장 가까운 앞의 `55 8B EC` 프레임 시작 후보에서 다음 후보까지만 선형 디코드해 명령 위치를 확인했으며, 첫 후보 전은 세그먼트 오프셋 0부터 검사했다. 명령 종류뿐 아니라 목적지 오프셋과 세그먼트 피연산자도 대조했다. FAR 284개와 near 25개 모두 경계·목적지 검사를 통과했다. 이는 명령 위치와 정적 목적지를 검증한 것이며, 각 호출의 실행 경로 도달성을 증명하는 결과는 아니다. 네 간접 콜백 디스패치 명령도 슬롯 값과 호출 피연산자를 재디코드해 확인했다. 호출 명령 인자를 제외한 전체 파일의 FAR 포인터 값 검색에서도 출력 경로의 간접 대상은 세 슬롯(`3342:66D8`, `66DC`, `675C`)에서만 발견됐다. 전체 파일 바이트 검색에서는 `0x4A1DA`에서 문자열표 그룹 선택 호출처럼 보이는 패턴 하나가 더 나왔지만, 해당 오버레이 `32AE`는 `0x4A1DD`에서 끝나므로 5바이트 명령이 다음 세그먼트까지 걸친 가짜 후보였다. 이 후보는 제외했고 실제 선택·해제 호출 수는 5개다. 호출 위치·인자·오버레이 매핑·콜백 주소·검사 결과는 호출 지점 CSV와 정적 xref JSON에 보존했다. EXE SHA-256은 `99f44e83b309dd826f3dbc5068c61679bb68047eed8d738dcef594ba0eef7552`다.

`3342:99C5`는 실행 파일에 미리 들어 있는 문자열이 아니다. 파일의 해당 위치는 0으로 채워져 있으며 런타임에 포맷 결과를 담는 버퍼다. `3342:2C32`, `3342:2C4E`, `3342:3768`의 실제 바이트열은 각각 `"%u"`, `"%u."`, `"%d"`다. 이 포인터들을 화면 문구로 분류하면 안 된다.

#### 포맷 함수 위의 전체 출력 헬퍼 경로

포맷 함수의 직접 참조만으로 화면 출력 경로를 다 셀 수 없다. 상주 세그먼트 `0EED`에는 문자열을 준비하고 대화상자·상태 메시지·게임 정보 패널에 넘기는 헬퍼가 세 개 더 있다. FAR 참조뿐 아니라 같은 세그먼트 내부의 near 참조까지 합치면 호출 위치는 각각 7, 26, 9개다. 전체 위치와 원본 파일 오프셋은 호출 지점 CSV에 기록했다.

##### 게임 정보 패널 `0EED:0F1A`

이 함수는 선택된 게임 레코드와 상태를 읽고 여러 줄의 정보를 공통 포맷 출력 함수에 전달한다. 코드 안에서 확인한 문자열표 인덱스는 `DUNE.ENG[6]` Harvest, `[49]` DMG, `[84]` 위치 지정, `[85]` 목표 지정, `[46]` 진행률, `[89]` 전력 정보, `[161]` 프리깃 도착, `[160]` 프리깃 대기, `[88]` 향신료 저장량이다. 레코드에서 읽는 동적 인덱스·수치도 있으며, `3342:3768`의 `"%d"`로 숫자를 출력한다.

호출 위치는 `0EED:20B9` (near), `044B:03A0`, `077B:01B5`, `1223:07DA`, `1836:1091`, `3208:6173`, `3208:6186`, `3208:61A5`, `3208:61CA`다. 이 주소들은 여러 게임 갱신·이벤트 코드에서 같은 정보 출력 함수를 부른다. 실행 중 각 호출이 선택하는 레코드와 분기는 정적 호출 위치만으로 특정 게임 상태에 대응시킬 수 없으므로 화면 이름을 임의로 붙이지 않았다.

null 포인터를 넘기는 FAR 포맷 호출은 14개다: `328B:0019`, `32A3:000E`, `3208:3901,393E,424E,528F,652D,654B,6DB4,7241,7892,CA48,D17C,D543`. near 포맷 호출 중 `0EED:02C8`도 같은 종류다. `0EED:1E65`는 null 문자열 여부를 검사하기 전에 옵션의 폰트 슬롯과 스타일을 처리하고, null이면 문자열 폭 계산과 문자 루프로 가지 않고 반환한다. 따라서 이 15개 호출은 화면 문구가 아니라 폰트·스타일·위치 상태 변경이다.

`29C7:0004`를 직접 호출하는 FAR 지점은 8개다. `0EED:1FEF`는 공통 포맷 함수의 실제 출력 분기이고, 나머지 7개는 포맷 함수를 우회해 문자 루프를 직접 부르는 경로다. 모두 같은 FNT 글리프 콜백을 이용한다.

포맷 호출, 직접 문자 루프, 폭 계산의 상주·오버레이 호출 인벤토리를 분리했다. 문자열 폭 합산 22 FAR 호출은 `0EED:1FC3,1FD5`, `2BBE:0003, 2BC0:002D`, `2CA0:0918,0964`, `328E:0017,0035`, `3208:C40A,C41E,C436,C44B,CC0C,CC20,CC38,CC4D,D18A,D557,D577,D58D,D6C5,FBDB`다. 직접 문자 폭 조회는 FAR `0EED:01DE,021A`와 near `2326:0058`이며, 이 중 문자열 폭 합산 내부 near 호출은 앞의 엔진 규약 절에서 설명했다.

이 절의 호출 대상·인자·폰트 상태 참조 목록은 정적 xref다. 정적 xref만으로 특정 플레이 상태에서의 도달성은 증명하지 않는다. 실제 시작 폰트와 타이틀 메뉴 출력 경로의 런타임 도달성은 아래 디버그 실측 절에 별도로 기록한다. 그 실측은 정적 인벤토리의 107개 참조 전체를 런타임에서 실행했다는 뜻은 아니다.

이 목록은 지정한 원본 EXE 안의 직접 FAR CALL 참조를 인벤토리화한 것이다. 런타임 함수 포인터의 호출 대상은 정적 참조가 아니라 해당 함수 포인터 테이블을 별도로 확인했다. 다른 버전 EXE나 별도로 패치한 실행 파일의 호출 수까지 대표하지 않는다.

## 한글화 구현에 적용되는 엔진 규약

- 원본 FNT는 코드 바이트를 직접 슬롯 번호로 쓴다. 유니코드→글리프 대응표는 없다.
- 원본 폭 계산, 정렬, 줄바꿈, 출력 루프는 1바이트 1글자다. 2바이트 조합 토큰을 추가하면 이 경로들을 함께 바꿔야 한다.
- 폰트 높이·폭 메트릭은 메뉴 상자, 행 pitch, 문자열 줄 간격에도 영향을 준다. 메뉴 박스 자체는 FNT나 CG가 아니라 별도 UI 코드가 그린다. 상세한 상자 계산과 하단 경계 실패 원인은 기존 메뉴 문서에 기록돼 있다.
- 글리프 비트맵 렌더러와 문자 배치 엔진은 분리돼 있다. 글리프를 잘 만들어도 폭 표, 셀 전진, 줄 간격, 정렬 폭 계산이 맞지 않으면 메뉴나 게임 창에서 서로 다른 문제를 만든다.

## 주소·폭·픽셀 높이의 해석

기존 엔진 개요의 메뉴 폰트 항목은 오프닝 폰트 로드 지점을 메뉴로 오인한 기록이었다. 이 항목은 이 문서의 “메뉴와 오프닝의 서로 다른 정적 경로”에 맞춰 수정했다. 과거 팔레트 분석이나 10×10/16×16 적용 문서는 각각 당시 시험 범위에 한정해 그대로 두고, 같은 렌더러 설명을 복사해 반복하지 않는다.
