# 보안 질문 생략 시 화면 준비와 대기의 경계

보안 질문의 입력 루프만 생략하면 멘타트 배경·회색 패널과 기존 대기가 남을 수 있다. 화면을 준비하는 호출, 질문 입력, 공통 정리와 다음 임무 상태는 각각 다른 처리다.

## 호출 순서

호출자는 `1223:040C`에서 정복 지도를 검게 페이드하고 `0455`에서 페이지 2를 페이지 0으로 복사한다. `045D`가 `32DD:1099`의 보안 함수를 부른다. 보안 함수는 원래 멘타트·질문 화면을 준비한 뒤 입력을 수행한다.

보안 함수 안의 WSA 포인터만 0으로 만들거나 질문 CALL만 제거하면 그 앞에서 수행한 배경·페이지 복사·팔레트 처리까지 취소되지 않는다. 반대로 준비를 건너뛰고 임의 위치로 점프하면 호출 규약과 다음 상태 설정을 놓칠 수 있다.

## 스택과 성공 반환

CALL 앞에 인자를 PUSH한 상태에서 CALL만 NOP 처리하면 원래 정리 명령이 맞는지 확인해야 한다. `PUSH CX` 등 남은 인자와 후속 POP·ADD SP가 균형을 이루지 않으면 저장 레지스터나 반환값이 잘못된다. 원래 프롤로그·공통 에필로그·RETF 규약을 유지해야 한다.

## 팔레트와 대기

팔레트 함수 `23A3:0000 → 00AB`는 RGB 768바이트를 단계적으로 바꾸고 `0226..0237`에서 `DS:7734/7736` 타이머를 기다린다. VGA DAC 포트 03C8/03C9와 수직 귀선 03DA를 사용한다. 기간 인자 15는 15초라는 뜻이 아니다.

임무 종료 검사에 예약되는 300틱은 브리핑 진입의 강제 대기가 아니다. 실제 첫 설명 전 대기는 공통 설명 함수의 30틱 가산과 구분해야 한다. 정적 호출 구조만으로 파일 로딩·지도 정리·WSA 준비의 실시간 소요량을 계산할 수는 없다.

최종 처리는 보안 성공 정리, 임무 설명 대기 상태에서의 팔레트 복원 억제, 첫 문구의 30틱 가산 제거를 조합한다. 세부 주소는 [전환 구조](security_briefing_transition.md)를 따른다.
