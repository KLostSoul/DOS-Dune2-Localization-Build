## 대상과 결론

사용자가 직접 실행한 배치는 `build/dalmuri672-english-subtitles-skip-security-question/run_dalmuri639.bat`이다. 이 배치가 마운트하는 후보 EXE를 분석했다.

- SHA-256: `efa74d8b44d85065eadb79c00aa47e957b26b0147a9238966142289990a8092f`
- 크기: 382,066바이트
- 사용자 관측: 회색 화면과 지연이 계속됨
- 당시 작업: 정적 역분석. 이 분석 단계에서는 게임을 실행하거나 실행 파일을 패치하지 않음

당시 생략 후보의 분기는 보안 장면의 화면 준비보다 뒤에 있었다. 그 분기에 도달하기 전에 멘타트 배경을 준비하고, 화면 전체를 표시 페이지로 복사하고, 타이머를 기다리는 팔레트 전환을 두 번 호출했다. 따라서 문구·초상 WSA와 뒤쪽 응답 루프를 없애도 중간 화면과 전환 대기가 남았다.

별도 결함도 있다. FAR 반환을 하는 함수를 `PUSH CS; CALL near`로 호출하던 부분에서 CALL만 NOP으로 바꿨다. 남은 `PUSH CS` 때문에 스택이 2바이트 어긋나고 함수 끝의 SI·DI 복원이 잘못된다.

이전에 원인으로 단정했던 뒤쪽 `0x78` 응답 대기 루프는 해당 후보의 진입 CFG에서 도달하지 않았다. 현재 증상을 그 루프가 계속 실행되기 때문이라고 설명한 것은 잘못이었다.

## 상위 호출자

실제 호출자는 상주 함수 `1223:02A9` 안에 있다. `DS:38A6`이 1 또는 7일 때 다음 경로를 실행한다.

1. 선택 처리 호출자에서 팔레트를 어둡게 한다.
2. 화면 페이지를 복사한다.
3. 파일 `0x1728D`, `1223:045D`에서 `CALL FAR 32DD:0039`를 실행한다. 원시 바이트는 `9A 39 00 DD 32`다.
4. 반환된 AX가 0이면 종료 경로로 가며, 0이 아니면 호출자가 오버레이를 정리하고 상태 플래그와 다음 처리 시각을 설정한 뒤 반환한다.

이 호출을 복원했으므로 이전 문서의 "보안 질문 함수 호출자를 찾지 못했다"는 상태도 정정한다.

## 남은 대기 코드

`23A3:0000`은 `23A3:00AB`를 호출한다. 이 함수는 현재 팔레트와 목표 팔레트의 RGB 768바이트를 비교하고, 색 성분을 단계적으로 바꾸며, 각 단계에서 `DS:7734/7736` 타이머가 목표값에 도달할 때까지 반복한다.

정확한 타이머 대기 명령은 `23A3:0226..0237`에 있다. 갱신된 팔레트는 VGA DAC 포트 `03C8/03C9`로 출력하며 `03DA`를 읽어 수직 귀선을 동기화한다. 당시 후보는 이 전환 함수를 두 번 그대로 호출했다. 기간 인자 15를 15초라고 해석하면 안 된다.

반면 이전에 지목한 파일 `0x5177E`, 실제 주소 `32DD:166E`의 `ADD DX,0x78`은 해당 진입 CFG에서 도달하지 않았다. 이 부분만 더 바꿔서는 앞에서 이미 실행되는 화면과 대기를 제거할 수 없었다.

REA Evidence: `ev_cd6d4b360f5e3b4eb025e2277373ef3c316dc3bbc935300d6a9cc57f03623f59`, `ev_704216df171272c4888f71d2666dc34683c702674839ea67b6c92a6af28cd8ee`, `ev_53de43eb31276565d1456db70af9a6206c433fb784756b5d4d5786d6603a4b02`.

## 이전 CALL 생략 패치의 스택 결함

원래 호출은 `PUSH CS; CALL near 32DD:0AB8`이며, 호출되는 함수는 `RETF`로 반환한다. 즉 PUSH CS와 near CALL이 함께 FAR 호출의 반환 주소를 만든다.

당시 후보 파일 `0x51302`부터의 바이트는 다음과 같다.

```text
0E 90 90 90 83 C4 12
PUSH CS
NOP / NOP / NOP
ADD SP,12h
```

CALL이 사라져 CS를 소비할 RETF도 실행되지 않는다. `ADD SP,12h`는 원래 18바이트 인자만 치우므로 CS용 2바이트가 남는다. 함수 진입에서 로컬 32바이트와 저장 SI·DI 4바이트를 사용하므로, 정상적인 에필로그 직전 SP는 `BP-36`이어야 한다. 현재는 `BP-38`이다. 따라서 `POP DI; POP SI`가 원래 저장 위치를 읽지 않는다. `MOV SP,BP`가 최종 반환 주소 위치는 복구하지만 SI·DI 값까지 복구하지는 않는다.

이 결함은 정적으로 확인됐지만, 회색의 실제 색값을 이 레지스터 손상 때문이라고 단정하지 않는다. 화면 준비와 팔레트 대기가 앞에서 실행되는 원인과 구분한다.

## 0cce 후보에서 페이드 뒤 정복 지도와 지연이 나타나는 이유

사용자는 보안 화면을 건너뛴 뒤 페이드가 끝나면 정복 지도 화면이 나타나고, 임무 설명으로 넘어가기까지 지연된다고 확인했다. 이 동작은 후보 EXE의 현재 호출 순서와 일치한다.

호출자 `1223:02A9` (`FUN_2223_02A9`, Ghidra 선형 주소 `0x224D9`)의 관련 순서는 다음과 같다.

1. `1223:03E6`에서 선택 문구 `DS:60C9`를 그리는 함수를 호출한다.
2. `1223:040C` (`0x2263C`)에서 원래 팔레트 페이드를 호출한다.
3. 첫 번째 또는 일곱 번째 미션이면 `1223:0432` (`0x22662`)에서 화면 자원 처리를 호출한다.
4. `1223:0455` (`0x22685`)에서 `32D5:0007(0,0,0,0,40,200,2,0)`을 호출한다. 이 호출은 320×200 화면 페이지 2를 페이지 0으로 복사한다. 따라서 페이드가 끝난 뒤 보이는 정복 지도는 화면 버퍼의 우연한 잔상만이 아니라, 질문 함수에 들어가기 직전에 호출자가 명시적으로 표시하는 페이지다.
5. `1223:045D` (`0x2268D`)에서 보안 함수 게이트를 호출한다. 현재 패치는 보안 함수가 성공값 1을 반환하게 한다.
6. 반환 뒤 `1223:04CA` (`0x226FA`)부터 화면 자원 정리와 상태 설정만 실행한다. `1223:04EF` (`0x2271F`)에서 `DS:38B2=1`, `1223:04F5` (`0x22725`)에서 `DS:3792=0`을 기록한다.
7. `1223:04FB..050C` (`0x2272B..0x2273C`)에서 다음 처리 시각을 현재 시각보다 `0x12C`(300) 뒤로 기록한 다음 반환한다. 같은 함수의 앞부분은 이 시각에 도달하기 전 호출되면 본문을 건너뛰고 바로 반환한다.

그러므로 관측된 두 현상은 각각 호출자 안의 별도 동작에서 나온다.

- **페이드 뒤 지도 화면:** 페이드가 끝난 다음의 전체 화면 페이지 복사(`1223:0455`)가 정복 지도 페이지를 표시한다. 보안 함수의 조기 성공 반환은 이 복사 호출을 건너뛰지 않는다.
- **임무 설명 전 지연:** 성공 반환 후 호출자가 다음 처리를 300틱 뒤로 예약하고 반환한다. 이 함수에는 임무 설명 화면 호출이 없으므로 `AX=1`만으로 임무 설명이 즉시 시작되지 않는다.
