## 페이드 뒤 지도 페이지가 다시 드러나는 코드

보안 호출자는 `1223:040C`에서 페이드아웃을 실행한 뒤 `1223:0455`에서 기존 페이지 2를 페이지 0으로 복사한다. 현재 후보는 보안 함수의 멘타트 화면 준비를 모두 생략하므로 이 페이지가 보안 화면으로 덮이지 않는다.

여기에 다음 반복의 `044B:01AA`가 상태 `38B2` 검사보다 먼저 `044B:0559`를 호출한다. 이 함수는 색상 애니메이션 타이머가 만료되었을 때 `DS:3C26/3C28`의 게임 팔레트를 `23A3:003A`에 넘긴다. 해당 호출 명령은 `044B:05C2`, `06B9`, `073A`에 있다. 첫 분기는 60틱, 다음 두 분기는 각각 3틱과 5틱 단위로 갱신 시각을 설정한다.

`23A3:003A`는 `29AA:0000`을 호출한다. 이 드라이버는 팔레트 캐시 `DS:712E`와 RGB 768바이트를 비교하며 실제 VGA DAC 포트 `03C8/03C9`에 색을 쓴다. 따라서 검은 페이드 상태에서 게임 팔레트를 재적용하면 화면 메모리에 남은 페이지가 다시 보인다. 이 팔레트 복원 뒤에야 `38B2` 분기가 시나리오 로딩과 브리핑 준비를 실행한다.

이는 원본 메인 루프에 남은 팔레트 갱신 호출의 정적 경로다. 현재 증상에서 어느 타이머 분기가 실제 실행되었는지는 새 실행의 레지스터·타이머 기록으로 측정하지 않았다. 보고된 지도 노출과 일치하는 명령 경로를 찾은 것이며, 모든 실행에서 세 분기가 전부 호출된다고 주장하지 않는다.

수정해야 할 전환 조건은 **브리핑 진입이 예약된 다음 메인 반복에서 이전 화면의 팔레트를 먼저 복원하지 않도록 하는 것**이다. 시나리오와 브리핑 첫 프레임 준비까지 페이드아웃 상태를 유지하고, 기존 `3314:0F2C`의 페이드인으로 표시를 재개해야 한다. 공통 설명 함수 안에서도 `044B:0559`가 쓰이므로 이 함수를 전역으로 없애면 브리핑과 게임의 원래 색상 애니메이션까지 바뀐다. 문제 지점은 상태 분기 직전의 호출 순서다.

## 300틱 지연이라는 이전 결론 정정

따라서 이 300틱을 보안 질문과 임무 설명 사이의 강제 대기라고 단정한 이전 설명을 철회한다. 실제 브리핑 전 경로에는 시나리오 로딩·4096개 지도 항목 정리·객체 상태 구성·문자열 및 WSA 준비가 있다. 공통 설명 함수 자체에도 기존 30틱 초기 타이밍과 WSA 진행 상태가 있다. 각 작업의 실제 소요 시간과 사용자가 본 지연 전체의 시간 배분은 이번 정적 분석으로 측정하지 않았다. 임의로 300틱을 제거하는 수정 근거로 사용하면 안 된다.

### 원인과 수정

앞서 식별한 메인 루프 순서에서 `DS:38B2=1`은 보안 질문을 성공 종료한 뒤 임무 브리핑을 준비하라는 상태다. 그런데 메인 루프는 이 상태를 분기하기 전에 기존 게임 팔레트를 갱신하는 `044B:0559` 호출을 먼저 실행할 수 있었다. 페이드아웃이 끝난 화면에 이전 게임 팔레트가 다시 적용되어 전환 중 정복 지도 화면이 드러날 수 있는 순서였다.

실행 파일 오프셋 `0x9258–0x9262`의 메인 루프 코드를 조건부로 바꿨다. `DS:38B2`가 브리핑 대기값 1이면 그 반복에서만 `044B:0559` 팔레트 갱신을 건너뛰고, 원래 상태 처리(`044B:01B4`)로 간다. 상태가 1이 아닌 일반 게임 반복에서는 기존 팔레트 갱신 호출 뒤 원래 경로(`044B:0209`)로 간다. 따라서 팔레트 갱신 함수를 전역 제거하거나 새 브리핑 엔진으로 대체한 수정이 아니다.
