# 보안 질문 종료에서 임무 설명으로 이어지는 상태 경로

## 확인된 흐름

보안 질문이 끝난 다음 임무 설명으로 이어지는 원래 경로가 존재한다. 보안 함수 안에 브리핑을 직접 호출하는 명령이 없다는 이유로 그 연결을 찾지 못했다고 설명한 이전 분석은 잘못됐다. 다음 메인 루프의 상태 분기로 연결된다.

| 순서 | 실제 원본 모듈 주소 | 동작 |
|---|---|---|
| 1 | `1223:045D` → 게이트 `32DD:0039` → 본체 `32DD:1099` | 보안 질문 함수 호출. 분석 표본는 `32DD:10AA`에서 성공값을 넣고 공통 에필로그 `16B8`로 이동한다. |
| 2 | `1223:04EF`, `04F5` | 정상 완료 후 `DS:38B2=1`, `DS:3792=0` 설정. |
| 3 | `044B:03FD`의 호출에서 복귀한 뒤 같은 메인 루프의 다음 반복 | 메인 루프를 끝내거나 `3283` 호출자까지 반환해서 다음 화면을 찾는 경로가 아니다. |
| 4 | `044B:01AA` → `044B:0559` | 상태 분기 직전 기존 팔레트 애니메이션 갱신 실행. 아래 화면 노출 문제와 연결된다. |
| 5 | `044B:01AD`, `01C5` | `38B2==1` 검사 후 가문 `3A2C`와 시나리오 `38A4`를 넘겨 `3314:0020` 게이트 호출. 이 게이트의 본체는 `3314:0000`. |
| 6 | `3314:0000` → `001E` | 시나리오 로딩 및 상태 준비. 로딩 성공 후 `0091`에서 지도·유닛·건물 상태 등을 초기화한다. |
| 7 | `3314:0010..0019` → `3314:0C06` | `3794==0`이면 임무 브리핑 진입. |
| 8 | `3314:0C06` → `0C93` → `0E44` | 가문별 임무 문자열 번호 `38A6*4+4`와 `DS:8D99` 리소스를 전달해 설명을 준비한다. |
| 9 | `3314:0E5A` → `32DD:0020` 게이트 → `32DD:0000` | 멘타트 배경과 설명 화면 준비. |
| 10 | `3314:0F13`, `0F2C` | 준비된 페이지 2를 표시 페이지 0으로 복사하고, `3C26:3C28` 팔레트로 원래 페이드인 실행. |
| 11 | `3314:0F50` → `32DD:0034` 게이트 → `32DD:0AB8` | 원래 공통 멘타트 설명 출력 함수 진입. 폰트 상태 초기화 호출은 `32DD:0B60`, 공통 본문 포맷 호출은 `32DD:0DFF`. |

따라서 브리핑으로 가는 새 엔진이나 별도 점프 경로를 만들어야 한다는 이전 전제는 필요하지 않다. 기존 상태 전환과 시나리오 로더, 공통 설명 출력을 유지하면서 그 사이 화면·팔레트 상태를 맞추는 작업이다.

## 페이드 뒤 지도 페이지가 다시 드러나는 코드

보안 호출자는 `1223:040C`에서 페이드아웃을 실행한 뒤 `1223:0455`에서 기존 페이지 2를 페이지 0으로 복사한다. 분석 표본는 보안 함수의 멘타트 화면 준비를 모두 생략하므로 이 페이지가 보안 화면으로 덮이지 않는다.

여기에 다음 반복의 `044B:01AA`가 상태 `38B2` 검사보다 먼저 `044B:0559`를 호출한다. 이 함수는 색상 애니메이션 타이머가 만료되었을 때 `DS:3C26/3C28`의 게임 팔레트를 `23A3:003A`에 넘긴다. 해당 호출 명령은 `044B:05C2`, `06B9`, `073A`에 있다. 첫 분기는 60틱, 다음 두 분기는 각각 3틱과 5틱 단위로 갱신 시각을 설정한다.

`23A3:003A`는 `29AA:0000`을 호출한다. 이 드라이버는 팔레트 캐시 `DS:712E`와 RGB 768바이트를 비교하며 실제 VGA DAC 포트 `03C8/03C9`에 색을 쓴다. 따라서 검은 페이드 상태에서 게임 팔레트를 재적용하면 화면 메모리에 남은 페이지가 다시 보인다. 이 팔레트 복원 뒤에야 `38B2` 분기가 시나리오 로딩과 브리핑 준비를 실행한다.

이는 원본 메인 루프에 남은 팔레트 갱신 호출의 정적 경로다. 현재 증상에서 어느 타이머 분기가 실제 실행되었는지는 새 실행의 레지스터·타이머 기록으로 측정하지 않았다. 보고된 지도 노출과 일치하는 명령 경로를 찾은 것이며, 모든 실행에서 세 분기가 전부 호출된다고 주장하지 않는다.

수정해야 할 전환 조건은 **브리핑 진입이 예약된 다음 메인 반복에서 이전 화면의 팔레트를 먼저 복원하지 않도록 하는 것**이다. 시나리오와 브리핑 첫 프레임 준비까지 페이드아웃 상태를 유지하고, 기존 `3314:0F2C`의 페이드인으로 표시를 재개해야 한다. 공통 설명 함수 안에서도 `044B:0559`가 쓰이므로 이 함수를 전역으로 없애면 브리핑과 게임의 원래 색상 애니메이션까지 바뀐다. 문제 지점은 상태 분기 직전의 호출 순서다.

## 카운터 간격과 실제 로딩 시간의 차이

`1223:04FB..050C`의 `DS:608C/608E = DS:773C/773E + 300`은 같은 임무 종료 판정 함수의 다음 검사 시각이다. 메인 루프의 `38B2==1` 분기는 이 값을 검사하지 않고 `3314:0000`으로 들어간다. 또한 메인 루프가 `DS:31B0/31B2`에 300틱을 더하는 위치는 `3314` 호출이 끝난 뒤다.

따라서 이 300틱을 보안 질문과 임무 설명 사이의 강제 대기라고 단정한 이전 설명을 철회한다. 실제 브리핑 전 경로에는 시나리오 로딩·4096개 지도 항목 정리·객체 상태 구성·문자열 및 WSA 준비가 있다. 공통 설명 함수 자체에도 기존 30틱 초기 타이밍과 WSA 진행 상태가 있다. 각 작업의 실제 소요 시간과 사용자가 본 지연 전체의 시간 배분은 정적 분석으로 측정하지 않았다. 임의로 300틱을 제거하는 수정 근거로 사용하면 안 된다.

## FBOV 모듈과 호출자 주소

기존 FNT 실행 기록은 원시 스택과 호출자 바이트를 보존하고 있으므로 다시 대조할 수 있었다. 과거 분석기의 `3208` 범위는 FBOV 디렉터리 크기를 누적해 만든 큰 범위여서 실제 모듈 주소로 쓰면 안 된다.

| 관측 | 원본 EXE 파일 위치 | 분석 표본 파일 위치 | 실제 모듈 주소 |
|---|---|---|---|
| 임무 브리핑 초기 null 포맷 호출, 반환 `48A7:0B65` | `0x4E310` | `0x50C70` | `32DD:0B60` |
| 가문 설명 `House Ordos` 등의 공통 본문 포맷 호출 | `0x4E5AF` | `0x50F0F` | `32DD:0DFF` |

호출자 명령 창은 세그먼트 재배치 부분을 제외해 원본과 한글 표본의 실제 파일 위치에 대조한다. 브리핑 초기화와 가문 소개의 문자열 관측은 구분하며, 정적 공통 호출을 근거로 임무 본문 전체를 실행 관측했다고 해석하지 않는다.

`3283` 루틴의 메인 루프 반환 뒤에는 문자열 ID `0x141` (`DUNE.ENG #321`, `Thank you for playing Dune II.`) 출력과 종료 정리가 있다. 이 루틴 전체를 단순 종료 함수라고 부르는 것도 부정확하다. 시작·메인 루프 호출·종료를 감싸는 상위 루틴이며, 임무 전환은 **메인 루프가 아직 실행 중일 때** 처리된다. 그 반환 뒤를 브리핑 경로로 추적한 것이 잘못이었다.
