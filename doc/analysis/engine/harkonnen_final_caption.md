# 하코넨 두 번째 황제 영상의 마지막 자막과 입 애니메이션

## 최종 상태 — 2026-10-25

사용자가 하코넨 두 번째 황제 영상의 마지막 `DUNE.ENG #320` 자막과 추가 시간 동안의 입 애니메이션을 정상 확인했다. 이 기능을 확인한 빌드는 `build/translation-editor-20261025-210431-528829`다. 이후 [오르도스 #308 수정](ordos_final_caption.md)을 더한 `212812-887425`가 현재 실행 배치의 대상이며, 하코넨 전용 분기·구성 코드는 그대로 유지된다.

- EXE: `source/VIRGIN/DUNE2/DUNE2.EXE`, 387,330바이트.
- EXE SHA-256: `374c57cd53941224c31ddd817fd9a2d06f9abd40492d121ee2364f0e9f269627`.
- 현재 독립 빌드 경로 `tools/build_game.py`가 `scenes.harkonnen_patch()`를 호출한다. 에디터의 빌드 버튼도 같은 독립 명령을 실행한다.
- 사용자 확인 문구: 화면 유지판에 “제대로 작동한다”, 입 애니메이션 반복 수정판에 “제대로 수정되었다 에디터 빌드에 적용하고 문서에 기록해라”. 후자의 확인이 현재 최종판에 해당한다.
- 게임 실행 확인 주체는 사용자다. 에이전트의 검사는 정적 대조이며 게임이나 디버거를 실행하지 않았다.

## 원인과 적용 범위

원본 영어 게임에서도 #319 다음에 영상이 끝나고 #320이 표시되지 않는 것을 사용자가 확인했다. #320은 원본 자막 표 `DS:1E55`의 마지막 유효 항목에 존재하며, 문자열이나 글리프 누락은 아니다.

REA로 확인한 원본 `32F0:07B6`은 현재 자막의 카운터를 소진한 호출에서 다음 항목으로 이동하고, 다음 호출에서 그 항목을 출력한다. 반면 영상 재생기는 장면 시간과 프레임 종료를 기준으로 종료하며 미출력 자막을 끝까지 진행시키는 조건이 없다. 정적으로 실제 실행의 정확한 호출 횟수를 측정한 것은 아니므로 과거 가정 기반의 59회/64회를 실제 추적으로 사용하지 않는다.

적용 대상은 `32B1`의 **가문 ID 0·임무 8**, 즉 하코넨 두 번째 황제 영상 전용 분기 `00CF`다. 하코넨 첫 영상·아트레이데스·오르도스·오프닝·엔딩의 분기와 공통 자막 엔진은 변경하지 않는다.

## 최종 구현

원본 전용 장면표 `DS:1E35`의 32바이트를 실행 중 스택에 복사한다. 원본은 세 장면과 종료 항목으로 구성된다. 복사본에서 마지막 `EFINALA` 장면의 설정만 다음과 같이 바꾼다.

| 항목 | 원본 | 최종판 |
|---|---:|---:|
| 기간 단위 | 85 | 145 |
| 기간 증가 | — | 60단위 = 360틱, 약 6초 |
| 장면 플래그 | `0042h` | `0041h` |
| 재생 모드 | 원본 모드 2 | 원본 반복 모드 1 |
| 프레임 간격 계산용 값 | 모드 2의 WSA 프레임 수 27 | 48 |
| 명목 프레임 간격 | `85×6÷27 = 18`틱 | `145×6÷48 = 18`틱 |

원본 모드 1은 프레임 번호가 WSA 프레임 수에 도달하면 0으로 되돌린다. 같은 WSA를 열린 상태로 반복하므로 추가 시간에도 입이 움직인다. 장면 사이에 WSA를 다시 여는 방식이 아니다. 실제 프레임 간격은 원본과 마찬가지로 장면 준비에 사용한 시간과 정수 나눗셈의 영향을 받는다.

기존 `32B1:00F0` 호출에 원래 아홉 인자를 전달하되 장면표 포인터만 `SS:복사본`으로 바꾼다. 자막표 `DS:1E55`, 문자열 번호, 음성·팔레트 인자, 공통 자막·폰트 출력 경로는 그대로다. 원본 장면표를 직접 바꾸지 않는다.

## 메모리·FBOV 배치

- 전용 장면표는 스택 32바이트, 보존하는 SI·DI·ES는 6바이트를 사용한다. 호출 복귀 후 모두 원상복구한다.
- 폰트·치트 상주 코드, FNT·MAP, MZ 이미지 끝과 SS:SP, MZ 재배치 표를 이동시키지 않는다.
- 별도 DOS/XMS 할당을 추가하지 않는다. WSA 로딩과 프레임 복원은 기존 게임 경로를 사용한다.
- `32B1` 원본 코드 305바이트에 전용 구성 코드 70바이트를 덧붙인 새 디스크 사본을 FBOV 본문 끝에 둔다. 정렬과 원본 fixup 표를 포함해 디스크 파일은 400바이트 증가한다.
- 해당 스텁의 디스크 상대 오프셋과 코드 크기, FBOV 본문 길이만 갱신한다. 기존 오버레이 디스크 내용과 뒤쪽 자료를 보존한다.
- 원본 FBOV fixup 여섯 개 `012D,0128,0123,011D,0112,0006`을 그대로 복사한다. 새 구성 코드에는 재배치가 필요한 절대 세그먼트 즉시값을 넣지 않는다.
- 장면표가 SS에 있으므로 다른 오버레이 호출 중 `32B1` 코드가 퇴거되더라도 장면표 수명은 유지된다.

## 확인 근거

`tools/checks/check_harkonnen_second_scene.py`로 수정 전 `translation-editor-20261025-201722-624606`과 최종판을 대조했다. 결과는 최종 빌드의 `harkonnen-second-scene-check.json`에 있다.

- 공통 영상·자막 모듈 `32F0` 전체와 가문 선택 모듈 `3314` 전체가 같다.
- 다른 가문 분기와 공통 호출부, 원본 장면·자막 표가 같다.
- 기존 FBOV 디스크 본문 전체가 보존된다. 새 사본의 원본 코드에서는 하코넨 전용 분기의 3바이트 점프만 다르다.
- 상주 폰트·치트 코드, MZ 배치와 재배치, 달무리 FNT·유니폰트 FNT/MAP가 같다.
- 원본 fixup 보존, 새 명령의 분기·스택 균형과 로더 재배치 후의 안전성을 정적으로 검사했다.
- 이후 사용자가 최종판의 정상 동작을 확인했다. 다른 모든 영상을 새로 재생 확인했다는 뜻으로 확대하지 않는다.

## 폐기·중간판 구분

공통 영상 종료부를 바꿨던 두 실패 빌드 `202553-760623`, `204515-809137`과 해당 종료 후크·검사 코드는 사용자 지시로 휴지통에 보냈다. 현재 구현에 재사용하지 않는다. 당시 빌드의 저장 데이터 8개는 `build/preserved-saves/emperor-caption-failed/`에 따로 보존했다.

이후 `205725-700078`은 전용 장면표에 원본 모드 0의 화면 고정 구간을 추가해 마지막 자막은 출력됐으나 입이 멈췄다. 현재 최종판은 그 고정 구간을 사용하지 않고 마지막 장면 자체를 원본 모드 1로 연장한다.

## 현재 소스와 빌드 적용

- `tools/scenes.py`: 대상 확인, 전용 오버레이 사본과 FBOV 메타데이터 생성.
- `import/asm/scene/harkonnen-second-scene.asm`: 스택 장면표 복사와 마지막 장면 설정, 기존 공통 호출 연결.
- `tools/build_game.py`: 폰트 생성 완료 후 위 패치를 적용하고 `build-report.json`의 `harkonnen_second_scene`에 기록한다.
- `tools/check_final_build.py --only scenes`: 정적 격리·배치·스택 검사.

에디터는 독립 빌드 명령을 별도 프로세스로 실행한다. 패치 코드는 빌드 명령이 시작할 때 읽으며 현재 저장 CSV를 입력으로 사용한다. 위 빌드 식별과 해시는 해당 기능을 확인한 당시의 기록이다.
