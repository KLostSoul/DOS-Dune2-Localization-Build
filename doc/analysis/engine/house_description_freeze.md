## 확인한 무한 반복 결함

1. `32DD:1901`에서 현재 문자열 포인터를 BX에 읽는다.
2. `1904`에서 부모 프레임의 문자열 포인터를 1 감소시킨다.
3. `1907`에서 감소 전 포인터의 글자를 AL에 읽는다.

## 멘타트 설명 출력 경로 전수 대조 — 2026-10-21

멘타트는 가문·임무 본문과 같은 `32DD:1893` 문장 분할기를 호출하지 않는다. 항목명은 `2CA0:2357`, 멘타트 본문은 `0EED:1FEF`에서 공통 문자 출력 루프 `29C7:0004`로 직접 들어간다. 본문은 저장된 CR과 렌더러의 화면 오른쪽 경계 줄바꿈을 사용한다. 따라서 문장 분할 후크를 멘타트에 억지로 붙이는 것은 같은 경로의 적용이 아니다. 한글 토큰 폭·글리프 출력 후크는 공통 `29C7:0004` 콜백에 있으므로 멘타트에도 이미 적용된다.

현재 한글 PAK의 멘타트 143개 레코드(아트레이데스 47, 하코넨 49, 오르도스 47)를 정적으로 재독해했다. 143개 항목명과 143개 압축 설명을 번역 CSV의 토큰 스트림과 각각 바이트 단위로 대조했고 모두 일치했다. 모든 한글 토큰은 639음절 코드표에서 유효했다. NEW6P.FNT와 NEW8P.FNT는 각 226 슬롯(인덱스 `00h`–`E1h`)이다.

아트레이데스 설명 6번과 36번에 CP437 `FAh`(유니코드 가운데점 `·`)가 남아 있었다. `FAh`는 해당 폰트의 226개 폭·글리프 표 범위 밖이라 원본 FNT 조회가 표 경계를 넘는다. 이는 실제 출력 경로에서 확인된 잘못된 글리프 인덱스지만, 사용자 화면에서 보고한 멈춤의 직접 원인이라고 단정할 런타임 주소 증거는 없다. 같은 문자가 있던 `TEXTO.ENG[36]`, `CREDITS.ENG[26,36]`도 함께 정리했다.

번역 호환 치환에 `·` → `.`을 추가했다. 마침표는 기존 원본 FNT에 있는 글리프다. 새 후보는 `build/dalmuri639-wrapfix/korean-mentat-fontsafe`에 만들었다. 실행 파일은 이전 검증 EXE와 SHA-256 `b1cdad13ee4dfb88f5ecaf71930f28036247509082d3d822cc4ca1c81397e929`로 동일하고, 번역 PAK만 새 치환을 반영한다. 생성 후 멘타트 레코드 전부를 다시 확인해 번역 바이트 일치, 토큰 유효성, FNT 인덱스 범위를 통과했고 번역 스트림 어디에도 `FAh`가 남지 않았다. 게임은 실행하지 않았으므로 이 후보에서 정지 증상이 해소됐는지는 사용자가 확인해야 한다.
