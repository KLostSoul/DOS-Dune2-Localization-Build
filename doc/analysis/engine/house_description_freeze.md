# 설명문 분할과 포인터 진행 조건

## 포인터가 진행하지 않는 분기

가문 설명을 표시하는 모듈 `32DD`는 `1893h`의 문장 분할 함수를 호출한다. `18B6h`부터 앞으로 글자 폭을 합산하고, 한 줄의 폭을 넘으면 `1901h`부터 공백까지 뒤로 이동한다.

역방향 폭 조회에서는 다음 순서로 처리한다.

1. `32DD:1901`에서 현재 문자열 포인터를 BX에 읽는다.
2. `1904`에서 부모 프레임의 문자열 포인터를 1 감소시킨다.
3. `1907`에서 감소 전 포인터의 글자를 AL에 읽는다.
4. `190B`에서 글자 폭 콜백을 호출한다. 반환 위치는 `1910`이다.
5. `1913–191A`에서 포인터 위치의 공백을 검사하고 공백이 아니면 반복한다. 이 반복에는 폭 수치로 탈출하는 조건이 없다.

결함이 있었던 후크는 이 역방향 호출을 구별하지 않고, AL이 한글 선행 바이트이면 먼저 ForwardTokenValid 경로로 처리한다. 감소 후 포인터의 앞 음절 후행 바이트를 현재 음절의 후행 바이트로 오인하여 유효 토큰으로 판별하면 부모 포인터를 다시 1 증가시킨다. 원본의 감소와 후크의 증가가 상쇄되어 같은 위치를 계속 읽는다.

또한 ReverseTokenCandidate의 비교도 원본이 이미 포인터를 감소시켰다는 계약을 반영하지 않는다. 단순히 forward 분기 하나를 우회하는 것으로 역방향 한글 처리가 완성되는 것은 아니다.

## 포인터 진행 규칙

정방향과 역방향 이동을 같은 부작용으로 처리하면 원본의 감소와 후크의 증가가 상쇄될 수 있다. 메뉴의 단순 폭 합산이 정상이라는 사실만으로 설명문의 역방향 분할도 정상이라고 판정할 수 없다.

현재 구현은 판독기에서 문자와 소비 길이를 반환하고 각 원본 순회가 자신의 포인터를 갱신한다. 호출자의 부모 프레임을 추측해 수정하지 않는다. 폭 콜백과 문자열 소유권은 [폭 판독 계약](../fonts/dalmoori_width_contract.md), 실제 연결은 [원본 인터페이스](native_output_rebuild.md#한글-토큰과-원본-인터페이스)를 따른다.

## 멘타트 설명의 분할 규칙

멘타트 항목 선택은 `32E3:080F`에서 공통 설명 함수의 게이트 `32DD:0034`를 호출한다. 원시 CALL `9A 34 00 18 06`의 FBOV 선택값 `0618h`는 `32DD` 모듈이며, 게이트의 `CD 3F B8 0A 00`은 본체 `32DD:0AB8`로 연결한다. 본체는 `32DD:0BB1`의 near CALL로 `32DD:1893` 문장 분할기를 호출한다. 따라서 멘타트도 가문·임무 설명과 같은 공통 분할 경로를 사용한다.

항목명 출력 `32A5:091C`와 본문을 최종적으로 그리는 `0EED:1FEF → 29C7:0004`는 각각 다른 단계다. 최종 문자 루프 호출만으로 앞선 문장 분할이 없다고 판단하면 안 된다. 저장된 CR, 공통 설명의 분할과 문자 루프의 화면 오른쪽 경계 줄바꿈을 함께 구분해야 한다. 한글 처리는 공통 분할기의 문자 경계와 최종 문자 루프의 토큰 폭·글리프 출력 규약을 모두 지킨다.

멘타트 리소스 검사는 항목명과 본문이 가리키는 데이터, NAME·DESC·INFO의 청크 경계와 최대 읽기 길이를 함께 대조한다. 문자열 토큰이 유효하다는 사실만으로 파일 탐색과 버퍼 길이가 정상이라고 판정하지 않는다.

원본 NEW6P.FNT와 NEW8P.FNT는 각 226슬롯(`00h..E1h`)이다. 이 범위 밖의 부호를 원본 슬롯 번호로 그대로 넘기면 폭·비트맵 표의 경계를 벗어날 수 있다. 현재 부호의 토큰과 글리프 선택은 [달무리 출력 선택](../fonts/dalmoori_latin_symbols.md)을 따른다.
