# DOS MZ와 FBOV의 주소·게이트 판독

MZ 로더가 초기화 모듈을 정상 해석해도 파일 뒤의 FBOV 코드를 자동으로 함수·호출 그래프에 연결하는 것은 아니다. 보안 질문의 호출자를 찾으려면 스텁, 게이트의 목적지와 실제 페이로드를 함께 읽어야 한다.

## MZ 분석 표본

| 항목 | 값 |
|---|---:|
| 헤더 | 19,456바이트, 4C00h |
| 초기화 모듈 | 260,480바이트, 3F980h |
| 뒤쪽 오버레이·부가 데이터 | 102,130바이트 |
| 재배치 | 4,505개 |
| 적재 선형 진입 주소 | 10000h |

이 표는 원본 SHA-256 `99f44e83b309dd826f3dbc5068c61679bb68047eed8d738dcef594ba0eef7552`에서 파생된 분석 표본의 헤더 수치다. 생성 빌드의 크기를 고정하는 상수로 사용하지 않는다.

## FBOV 게이트와 본체

실제 보안 질문은 호출자 `1223:045D`에서 게이트 `32DD:0039`를 거쳐 본체 `32DD:1099`에 들어간다. 큰 디스크 블록을 `3208`로 통째로 해석해 얻은 `3208:3E3A`는 같은 바이트를 가리키는 분석용 배정이며 실제 모듈 주소가 아니다.

FAR CALL의 세그먼트 피연산자에는 FBOV 표 선택값이 들어갈 수 있다. 이를 일반 리얼모드 세그먼트로 그대로 해석하면 MZ 함수와의 연결을 놓친다. 리소스 이름 생성의 실제 목적지는 `044B:075D`다.

## 보안 리소스와 반환

데이터 `DS:25B7`은 `PROTECT` 이름이다. 가문 값 `DS:[3A2C]`로 `FHARK.WSA`, `FARTR.WSA`, `FORDOS.WSA`를 고르고 언어 리소스를 연다. 질문 처리 결과는 성공·정리·상위 상태 분기로 연결된다.

질문을 호출하는 코드만 없애면 준비 호출·스택 인자·실패 반환을 그대로 남길 수 있다. 성공값 1과 원래 에필로그를 사용하고 임무 설명 대기 상태까지 추적해야 한다. 전환 경로는 [상태 연결](security_briefing_reanalysis.md), 패치 위치는 [임무 전환](security_briefing_transition.md)을 따른다.
