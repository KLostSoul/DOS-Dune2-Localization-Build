## 증상과 수정 범위

사용자는 오르도스 두 번째 황제 영상이 마지막 `DUNE.ENG #308`을 출력하지 않고 끝난다고 보고했다. #308은 원본 자막표 `DS:1D81`의 마지막 유효 항목 `DS:1DA9`에 존재한다. 원본 장면표 `DS:1D61`의 마지막 EFINALA 장면은 기간 75단위·모드 2다. 공통 영상 재생기의 종료는 자막 표의 완료 여부를 기다리지 않는다.

기존 하코넨 수정과 같은 원본 반복 모드를 **오르도스 두 번째 영상 전용 분기**에 적용한다. 대상은 가문 ID 2·임무 8, `32B1:00B6`이다. 오르도스 첫 영상, 아트레이데스, 오프닝·엔딩과 공통 자막 엔진은 수정하지 않는다.

## 구현과 시간 설정

원본 32바이트 장면표를 SS의 임시 공간에 복사하고 마지막 장면 설정만 바꾼다. 종료 항목과 앞의 두 장면은 그대로다.

| 항목 | 원본 | 수정판 |
|---|---:|---:|
| 마지막 장면 기간 | 75단위 | 135단위 |
| 증가 시간 | — | 60단위 = 360틱, 약 6초 |
| 플래그 | `0042h` | `0041h` |
| 재생 모드 | 원본 모드 2 | 원본 반복 모드 1 |
| 간격 계산용 값 | WSA 프레임 수 27 | 50 |
| 명목 프레임 간격 | `75×6÷27 = 16`틱 | `135×6÷50 = 16`틱 |

같은 EFINALA WSA를 열린 상태로 반복해 추가 시간에도 입이 움직이게 한다. 하코넨의 명목 18틱을 그대로 쓰지 않고 오르도스 원본의 명목 16틱에 맞춘다. 실제 간격 계산에는 기존 장면 준비 시간과 정수 나눗셈이 적용된다.

기존 공통 호출 `32B1:00F0`에 원본과 같은 인자를 전달한다. 장면표만 SS 복사본으로 바꾸고 자막표 `DS:1D81`, 음성·효과 표 `DS:1DBD`, 팔레트 인자 `DS:1DC0`, 음악 값 `22h`는 유지한다. 문자열 내용이나 #307의 표시 카운터를 임의로 바꾸지 않는다.

## 메모리와 정적 대조

- 장면표 스택 32바이트와 SI·DI·ES 보존 6바이트를 사용하며 복귀 후 정리한다. 별도 DOS/XMS 할당은 추가하지 않는다.
- 폰트·치트 상주 코드, FNT/MAP, MZ 이미지 크기·SS:SP·재배치 표를 바꾸지 않는다.
- 하코넨 수정 모듈 375바이트 뒤에 오르도스 전용 코드 70바이트를 붙인다. 새 445바이트 모듈 사본, 원본 fixup 표와 정렬을 포함해 FBOV 디스크 본문에 464바이트를 추가한다.
- 하코넨 전용 분기와 코드 `0131..0176`은 그대로다. 기존 모듈에서 바뀌는 명령은 오르도스 전용 분기의 3바이트 점프뿐이다.
- 원본 FBOV fixup 여섯 개를 유지한다. 추가 코드에는 절대 세그먼트 즉시값을 넣지 않아 새 fixup이 필요하지 않다.
- `check_ordos_second_scene.py`는 직전 에디터 생성본 `translation-editor-20261025-211735-543862`와 대조했다. 다른 분기·공통 자막·원본 표·기존 FBOV 디스크 본문·폰트/치트 배치 보존, 스택 균형, 재배치 후 추가 코드 보존을 확인했다.
- 통합 검사 `check_harkonnen_second_scene.py`도 수정 전 `201722-624606`과 비교해 공통 영상/자막 모듈과 두 대상 외 분기가 유지되는 것을 확인했다.

결과는 확인 빌드의 `ordos-second-scene-check.json`, `harkonnen-second-scene-check.json`에 있다. 검사 과정에서 게임·디버거·CPU 에뮬레이션을 실행하지 않았다. 이후 정상 동작 확인은 사용자 실행 보고다.

## 일시 멈춤 보고의 구분

사용자가 처음에는 DOSBox 자체의 멈춤을 보고했으나, 같은 수정본에서 다시 출력된다고 확인한 뒤 이상 없이 작동한다고 확인했다. 그 사이 실행 파일을 추가로 수정하지 않았다. DOSBox 오류일 가능성은 사용자의 추정이며, 멈춤 원인이 확정되거나 별도 코드 수정으로 해결됐다고 기록하지 않는다.
